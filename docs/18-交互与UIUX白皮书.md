# 3MF模型管理器 · 交互与 UI/UX 白皮书

> 版本：v1.1　更新日期：2026-11-22
> 适用范围：主模型库（网格 / 列表）、打印回执、重复文件、失效文件、详情抽屉
> 本文是交互一致性的**约束文档**：新增视图或批量操作时，必须先对照这里的规则，再写代码。

---

## 一、总则：交互一致性六条

1. **同一手势，同一含义。** 长按 480ms 在任何卡片列表里都只表示一件事：进入编辑模式并选中按下的那一项。
2. **同一位置，同一动作。** 编辑模式的操作条固定在屏幕底部居中；「全选」「删除」「完成」的位置和顺序不随视图改变。
3. **勾选状态只有一个来源。** 全局 `state.selection`（Set）是唯一选择集；视图只在渲染时读它，不各自维护副本。
4. **危险操作必须分级且可确认。** 删除「模型文件」「回执记录」「单个副本」是三种不同危险级别，确认文案必须说清删的是什么、能否恢复。
5. **不做无声的破坏。** 任何删除都要二次确认；能恢复的走系统回收站，只删记录的要明说「不动模型文件」。
6. **视图隔离。** 切换视图时退出编辑模式并清空选择集；模型 id 与回执 id 绝不共用同一批勾选。

## 二、长按编辑模式（核心交互）

### 2.1 进入

| 规则 | 值 | 说明 |
| --- | --- | --- |
| 触发手势 | 在卡片上按住不动 | 鼠标左键 / 触摸均适用 |
| 时长 | **480 ms** | 主页面与回执视图完全一致 |
| 位移容差 | **8 px** | 超出即判定为拖动，取消长按 |
| 进入时 | 立即选中按下的那一项 | 操作条显示「已选 1 项」，不用再点一次 |
| 抑制误触 | 吞掉松手后的那次 click | `suppressClick`，避免进入模式又立刻取消选中 |
| 不触发区域 | 按钮、输入框、标签、链接 | 长按这些元素不进编辑模式 |

### 2.2 编辑模式中的行为

- 单击卡片 = **切换勾选**（不会打开详情、不会启动切片软件）。
- 卡片左上角显示勾选框；选中项用主题强调色描边 + 浅色底。
- 顶部统计条右侧的「模型批量操作」必须隐藏——它在回执视图里是危险的（见 §4.2）。
- 拖动仍然可用于归类；点快捷按钮仍然生效。

### 2.3 操作条（editbar）

统一结构，固定在底部居中：

```
[编辑模式] [已选 N 项] ── [全选] [迁移到分类] [删除] [完成]
```

- **全选**：只选当前视图可见的那些项；已经全选时按钮禁用。
- **迁移到分类**：只在模型库视图出现；回执视图必须隐藏（返回 `hidden`）。
- **删除**：按视图分发到各自的处理器，文案随视图变化（模型 = 「删除」，回执 = 「删除回执」）。
- **完成**：退出编辑模式并清空选择集。

### 2.4 退出

按优先级逐层关闭，一次按键只关一层：

1. 点击「完成」
2. 按 `Esc`
3. 点击空白区域（卡片本身不算空白）
4. 切换视图 / 刷新导致 `contentMode` 改变

退出时：清除 `state.editMode`、移除 body 的 `edit-mode` 类、隐藏操作条、清空选择集。

## 三、各视图的操作矩阵

| 视图 | 长按进入 | 可选操作 | 删除按钮实际动作 | 选择集内容 |
| --- | --- | --- | --- | --- |
| 模型库（网格 / 列表） | ✅ | 全选 / 迁移分类 / 删除 | `api.trash(ids)` → 系统回收站，可恢复 | 模型 id |
| 打印回执 · 成本账本 | ✅ | 关联模型 / 全选 / 删除回执 | `api.receiptsDelete(ids)` → 只删本机回执记录 | 回执 id（`rcp-…`） |
| 重复文件 | 按普通卡片规则 | 同上（模型语义） | 同模型库 | 模型 id |
| 失效文件 | 按普通卡片规则 | 同上（模型语义） | 同模型库 | 模型 id |
| 详情内副本切换 | ❌（用行内按钮） | 切换 / 删除单个副本 | `api.trash([单id])` → 回收站 | 不使用选择集 |

### 3.1 打印回执的账本语义

- **时间像账本**：卡片显示「几月几日 时:分 打印完成 / 打印失败」，不显示裸时间戳；成功与失败用同一套时间格式，只换动词。
- **允许手动关联模型**：每条回执都有「关联模型 / 更换关联」按钮，打开可搜索的模型选择器；自动匹配错、任务名和库里文件名不一致时由用户自己纠正。
- **关联不改历史**：只写 `receipts.json` 的 `modelId` / `modelTitle` / `linkedAt`，不碰模型文件、不重算打印时的成本与用料快照，也不改原任务名。
- **清除关联可回退显示**：选择「清除关联」后卡片恢复显示原任务名，回执本身保留。
- **清空 / 删除要留任务墓碑**：清空或单条删除时写 `seenJobs`（打印机 + 任务名 + 开始/结束时间），启动补录只认没见过的任务。否则监控历史里那两条已打印任务会在重启后又冒出来（2026-11-26 用户实测反馈「清空重启又刷新两个」）。
- **确认文案要说清「不会补回」**：清空确认框明确「只删除本机回执记录，不会动模型文件和模型库；清空后重启软件，也不会把已经看过的历史任务自动补回来」。
- **真正重打仍要记账**：墓碑只拦「同一次打印」；开始时间差 >2 分钟视为新任务，照常落回执，不能因为清空过一次就永久漏记。
- **编辑模式优先勾选**：长按编辑模式下点卡片只切换勾选，不打开关联选择器，避免误改绑。

**视图隔离实现要点**

- `app.js`：视图切换时若 `contentMode` 改变且在编辑模式，调用 `exitEditMode()`；`pruneSelection()` 在回执视图直接跳过（回执 id 不在模型列表里，会被误裁掉）。
- `bulkbar.js`：`syncBulkbar()` 在回执视图隐藏模型批量操作条。
- `app.js isBlankClick()`：`.rc-card` 与 `.card` 同属「内容」，点击不触发退出。
- `editmode.js`：`scopeTotal()` 按视图取总数（回执数来自渲染时写入的 `window.__receiptsIds`）。

## 四、删除安全规范

### 4.1 三个危险级别

| 级别 | 场景 | 确认文案必须包含 | 可恢复 |
| --- | --- | --- | --- |
| 高 | 删除模型文件（批量 / 单个） | 「移入系统回收站」「列出完整路径」 | ✅ 回收站 |
| 中 | 删除重复组里的单个副本 | 「只删除这一个副本」「其他副本不受影响」 | ✅ 回收站 |
| 低 | 删除打印回执记录 | 「只删除本机的回执记录，不会动模型文件或模型库」 | ❌ 明确说明 |

### 4.2 严禁串味

- **回执视图绝不调用 `api.trash()`**：那会按回执 id 去删模型文件，可能造成真实数据丢失。
- **模型批量操作条在回执视图必须隐藏**：否则上面的「删除」按钮会走模型删除路径。
- **回执选择集不能被模型列表裁剪**：`pruneSelection()` 必须按 `contentMode` 分流。
- 所有删除都要先 `confirmDialog`，失败逐条报告，成功后再刷新数据并退出编辑模式。

## 五、重复文件交互

普通视图中内容哈希相同的文件只显示一张代表卡，角标「重复 ×N」。

- **主页不提供展开入口**：卡片只有「重复 ×N」角标，不放「展开 N 个副本」按钮。要看同组其他文件就点开卡片，在详情里切换。
- 详情大图下方列出同组每个副本的完整路径，并显示各自的打印状态、大小、添加时间、备注摘要。
- 切换副本三种方式等价：点行、点「上一个 / 下一个」、按 `←` `→`。顶部显示「第 N / M 个」。
- 切换带轻微方向性淡入；**不弹 toast**——高亮、位置数字、主图切换已是即时反馈，连续切换时提示会堆叠遮挡界面。
- 副本行右侧垃圾桶 = 只删这一个副本（见 §4.1 中等级）。
- 侧栏「重复文件」视图仍按组展示全部成员，用于批量清理。

### 5.1 一键清除（每组留一个）

- **入口**：重复文件视图标题右侧「一键清除 · 每组留 1 个（N）」，N 是本次会移入回收站的个数；没有可清理的组时不显示按钮。
- **只处理内容完全相同的组**（`duplicateGroup`）。「疑似重复」（`similarGroup`）只靠文件名和体积相近判断，不参与一键清除，避免误删不同模型。
- **保留哪一个**：先看人工信息（备注、评分、收藏、分类、标签、打印次数），信息多的优先留；都一样时留最早入库的那份。内容既然完全相同，留「用户动过的那份」才不会把备注和评分一起删掉。
- **删到哪里**：走系统回收站（可恢复），同时把记录移出索引。不能只移索引——文件还在磁盘上，下次扫描会重新入库，用户会以为没清干净。
- **必须先确认**：确认框写明「共 N 组、保留 N 个、移入回收站 M 个」，并逐组列出保留哪个、删几个（超过 8 组折叠成「另有 N 组」）。取消不写任何数据。
- **失效副本不参与**：状态为 `missing`/`error` 的副本归「失效文件」视图处理，不在一键清除里删，否则回收站操作必然失败。
- **计数口径**：侧栏「重复」徽标只统计「组内 ≥2」的记录。清理后留下的那份仍带旧分组标记，按标记计数会让徽标虚高（2026-11-24 修复）。
- **页头与底栏必须同一口径**：重复文件页头、底栏统一显示「共 X 组 · Y 个文件」，不能一处写组数、一处写「共 1 个模型」；`state.specialMeta` 由 `duplicates.js` 的 `setSpecialMeta(groups, files)` 写入，`toolbar.syncToolbar()` 与 `app.updateStatusBar()` 优先读它（2026-11-26 修复）。
- **完全重复与疑似重复分两段**：`duplicateGroup` 是内容 SHA-1 相同；`similarGroup` 是文件名 + 体积相近的「疑似，请人工确认」。两者都计入侧栏「重复」徽标和页头「Y 个文件」，但「一键清除」只处理完全相同的组，避免误删不同模型。
- **同一组不重复列**：已被精确组收进去的 id 会从疑似组剔除，避免同一批文件在「完全重复」和「疑似重复」两段各出现一次。
- **回收站失败不静默、也不硬删**：单个文件移回收站失败时，仍把它降为副本（文件留在原处、记录标副本），toast 明确写「N 个文件没能移入回收站，其中 K 个保持原位、只标为副本（原因）」，不能出现「已合并 0 组」把整组卡死。
- **回收站按钮真的会动文件**：`plan.aliasIds` 是 id 字符串数组，调用 `_trashFile` 时必须按 id 取记录；误用 `a.id` 会让 `outcome[undefined]` 记失败、实际没尝试回收站（2026-11-26 修复）。
- **确认框要写清后果**：合并确认框说明「保留 X，其余 N 个降为副本」；带回收站时再补一句「系统回收站不可用会保留文件、只标副本，不会直接删除」。

### 5.2 同款变体（缩略图相同）

- **只认缩略图字节相同**：同一个模型复制、放大缩小、换颜色后重新导出，3MF 内容哈希和文件名都会变，但模型自带的缩略图通常不变。分组按缩略图文件 SHA-1 完全相同，不做 dHash 相似度阈值——9×8 缩小后，深色背景 + 中间亮物体的不同模型会撞指纹（真实库曾把肥鱼GTA、Lumina、奶龙、月高达聚成一组）。
- **不硬凑**：没有缩略图、占位 `.svg`、失效/隔离/解析失败、已是副本、已归「完全重复 / 疑似重复」的记录都不参与；空指纹绝不互聚。
- **组头写「缩略图相同」**：说明文案明确「不看文件名和几何形状」；主记录推荐理由固定含「最早入库的那一个」。
- **检查状态要可见**：页头显示「已检查 X 张缩略图 / 还有 X 个待检查 / 没有可用缩略图已跳过」，按钮写「重新检查缩略图」；还在检查时每 2.5 秒轮询刷新，不能停在旧结果上。
- **计数同口径**：页头与底栏同样用「共 X 组 · Y 个文件」，不用「共 N 个模型」冒充变体组数。
- **「保留最新 · 删旧版」一键按钮**：组头在合并按钮前提供，按文件修改时间选最新版本，其余旧版本降为副本并移入系统回收站；点击先弹确认框，写明「按文件修改时间判断」和「取消不执行」，不会一键静默删文件。

## 五之二、耗材库与默认耗材

- **手动新建为主，内置少量通用耗材**：首次启动从 `resources/builtin-filaments/` 写入 3 条通用耗材（含图片）；已有「品牌+名称+类型」相同的条目时跳过，不覆盖用户数据。除这 3 条外仍只允许手动新建，不提供「从预设添加」或自动探测入口。
- **筛选下拉用 `change` 事件**：原生 `<select>` 的点击不能在 click 阶段 `render()`，否则下拉刚弹出就被整块 DOM 替换、瞬间消失（2026-11-22 实际bug）。所有「改了就重绘」的控件统一走 `change`，click 阶段只做选中/打开。
- **默认耗材**：详情栏「设为默认」按钮单选一个耗材，卡片显示「默认」角标、按钮变「已是默认」；再点一次取消。删除默认耗材时自动清空默认指向，不留悬空 id。
- **默认耗材计价**：模型既没有 `filamentLinks`、也没有切片逐耗材用量时，按 `可信重量 × 默认耗材单价` 估算成本，`source='default'`，卡片显示具体金额（不再是 `¥??`），详情来源标注「按默认耗材估算」。设置/取消默认会触发成本重算。
- **耗材图片先裁后存**：点「换图片」选完 png/jpg 后，先弹裁切编辑器（拖框选范围、拖角/边改大小、框内拖动平移，比例可锁 1:1 / 4:3 / 16:9 / 原图，输出宽高可改），确认后才落盘。原图不入库——手机直出的大图当卡片图是纯浪费内存。
- **图片格式按文件头判定**：扩展名不可信，webp 改名成 `.png` 会让浏览器按 `image/png` 解码直接破图；非 PNG/JPEG 一律拒绝并提示。
- **图片地址是 `shelf://filaments/<hash>`**：`shelf` 是 standard 协议，`filaments` 在 URL 里是**主机名**而不是路径首段；协议处理函数必须按 `hostname` 判定，只判断 `pathname` 前缀会让耗材图片全部 404（2026-11-24 实际 bug：导入后整片破图）。

## 五之二·补：拓竹 → 快造 U1 转换的两个坑（2026-11-24 实测）

- **床变大要重新居中**：上游引擎只补 `printable_area` 的原点差（0.5 / 1 mm），不补尺寸差。A1 mini（180×180）→ U1（270×270）时每轴缺 45 mm，整盘内容贴在左下角，看着像「错位」，其实相对位置没错。我们在 `src/core/u1bedshift.js` 里把 `build item` 与 `assemble_item` 的平移同时补 (ΔW/2, ΔH/2)——两处必须一起改，Orca 读 assemble、Bambu 读 build item。
- **颜色压到 4 色是既有行为，不是新 bug**：U1 四个工具头，源文件超过 4 色必然合并。`data/u1-cache` 的历史报告显示从 2026-11-14 起就有 10→4、16→4 的记录；看起来「以前颜色能保住」是因为那些文件本来就 ≤4 色。
- **颜色默认全部保留**（用户 2026-11-24 决定）：引擎默认会把颜色压到 4 槽，而它对「整模涂色」（paint_color）的模型只能按对象级 extruder 统计用量——这类模型所有对象都是 1 号槽，用量全是 0，于是按颜色顺序把白色、橙色这类大面积色并掉（`scumon`：6 色，白→黄）。现在一律传 `keepAllColours`，源文件几种色就留几种，超过 4 色时在 Orca 里手动换料。
- **设置页可改回压色**：「颜色超过 4 色时」可选「保留全部颜色（默认）」或「自动压到 4 色」。该开关进缓存键，切换后不会复用旧的另一种结果。

## 五之三、设备移除与一键整理

- **移除入口始终有反馈**：设备卡片来自 `printersSnapshot()`，配置列表来自 `printersList()`。离线/失效设备可能只在快照里，移除动作必须按卡片 id 直接调用删除接口；不得只在配置列表里查，找不到就静默 `return`（2026-11-24 实际 bug：点「移除设备」没反应）。
- **只删本机配置**：所有移除入口（单卡「移除设备」、「移除失效设备」、「一键整理设备」）的确认文案都要明确：删除的是本工具保存的连接信息，不会重置打印机、不会影响正在进行的打印，之后可以重新添加。
- **「失效」判定保守**：只有快照中 `online=false` / `state='offline'` / `stateText='离线'` 的设备才列入失效清单；`连接中` 不算，避免 Wi-Fi 抖动时误删配置。
- **批量动作先给清单**：「移除失效设备」与「一键整理设备」都先弹确认框，逐条列出将添加/移除的设备；取消不写数据。
- **一键整理顺序**：扫描局域网 → 列出未配置的新设备 + 可移除的离线设备 → 用户确认 → 先添加、后移除。扫描时仍能连上的 IP 不进入移除清单，避免误删刚恢复的设备。
- **逐台添加仍保留**：扫描结果可单台「添加」，也可「添加全部新设备」；重复 IP 不再二次添加。

## 五之三、打印回执：完成判定与自动关联

### 5.3.1 完成判定必须「扛得住掉线」

- **状态要落盘**：每台设备的最近状态、任务名、进度、开始时间写进 `data/monitor/history.json` 的 `runtime`。只放内存的话，「打印中关掉软件 → 打完再打开」永远判不出完成，回执直接丢失（2026-11-24 用户反馈「打印成功没记上」）。
- **补判规则**：观察到「活动态 → idle」且最后进度 ≥ 95% 时，按完成记账（`inferred=true`）。低于 95% 更可能是取消，不记账。固件把 FINISH 直接跳成 IDLE、或掉线重连错过完成帧时靠这条兜住。
- **任务名要留底**：拓竹进入终态会收起任务块（`job=null`）。回执标题取「当前推送的任务名 → 最近一次已知任务名」，绝不允许落成「当前任务」这种占位文案。
- **去重**：同一 `printerId + jobName` 在 6 小时窗口内只落一条；重启补判、重连重复推送都不会刷出第二条。

### 5.3.2 自动关联：名字大致匹配就够

- **为什么要模糊**：同一模型分多次打印会出现 `_plate_2`、`(3)`、尾部编号、`_PETG_6h4m` 等变体，精确匹配会全落空，回执永远显示「关联模型」。
- **归一规则**：去掉扩展名、U1 转换哈希、盘号、括号编号、copy/副本、材料与时长尾标、尾部 1~3 位编号，反复剥到不再变化。
- **打分**：归一后相等 ≈1.0；包含关系 0.86~0.96；其余按字符二元组 Dice。最终分 = 归一分 ×0.75 + 原始名字相似度 ×0.25。
- **宁可漏不可错**：只有「归一后名字、原始名字相似度、公共前缀长度」三项都打平才算分不清（计入 `ambiguous`，不关联）；低于 0.72 直接放弃。
- **同名基础名要挑对**：`沙奈朵拆` 与 `沙奈朵拆(3)` 归一后都是「沙奈朵拆」，此时按原始名字的公共前缀决定——`沙奈朵拆(3)_plate_2` 必须连 `沙奈朵拆(3)`。早先只卡分数差会把这种情况误判成「太像不敢猜」（2026-11-24 实测）。
- **入口两处**：打印完成时自动试一次；回执页「自动关联（N）」按钮与每次启动的后台补跑，给历史回执兜底。
- **只写关联**：自动关联只写 `modelId/modelTitle/linkedAt/linkedManually=false`，不改成本与用料快照；改错了仍可「更换关联」。
- **不自动改打印状态**：模糊匹配只用来记账；只有精确匹配或分数 ≥0.9 时才回写模型「已打印」，避免误标。

## 六、视觉与反馈约定

- **反馈优先级**：DOM 状态变化（勾选 / 高亮 / 位置数字） > 轻量动画 > toast。能用前两者表达就不要弹 toast。
- **动画**：WAAPI 轻量淡入，时长 140–180 ms，位移 4–14 px；同模型局部刷新不播动画，避免每次点收藏都像重开窗口。
- **toast 只用于**：操作结果（成功 / 失败 / 需用户注意）、无法用界面状态表达的提示。错误 toast 必须可追溯（探针会监听 `.toast-error`）。
- **危险色**：仅用于删除按钮的 hover 态与确认弹窗；常态保持低调，不喧宾夺主。
- **来源链接状态**：卡片地球按钮由 `sourceUrl` 唯一决定视觉状态——有合法 `http(s)` 链接时加 `has-source`，显示语义绿底白图标；没有链接时保留原灰色，不显示可点击暗示。网格与列表视图必须一致，hover 只做同色系微调，不回落成灰底。
- **溢出**：长路径统一 `text-overflow: ellipsis` + `title` 全称提示；详情行内元数据最多两行，不换行撑高。
- **图标只有一个**：应用内标题栏、窗口/任务栏、桌面与开始菜单快捷方式、绿色版 exe、安装包，全部使用 `resources/app.ico`（紫色层叠 logo）。打包时必须用 rcedit 把 ico 写进 exe 的 PE 资源——只把 `app.ico` 复制到产物目录是不够的，exe 会保留 Electron 默认的原子图标（2026-11-24 用户反馈「图标不一致」）。
