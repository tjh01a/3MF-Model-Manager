## A · 几何指纹：识别「同模型不同版本 / 改色 / 缩放」

### A.1 目标与用户故事

> 我下载过 5 次 3D Benchy，有的是改了颜色的，有的是放大 125% 的，有的是别人重切过的。文件名和哈希全不一样，但它们是同一个模型。我希望软件能把它们归到一组，让我知道「这个模型我已经有了」。

判定目标：

| 情况 | 期望结果 |
|---|---|
| 只改颜色 / 改打印参数后重切片 | 判为**同一模型**（相似度最高档） |
| 等比缩放（如 125%、200%） | 判为**同一模型的缩放版** |
| 镜像、旋转、平移、摆放位置变化 | 判为**同一模型** |
| 轻微修改（加个小孔、切掉一部分、加个底座） | 判为**疑似同款变体**，由用户确认 |
| 完全不同的模型 | 不分组 |

### A.2 为什么现有方案不够

- `record.hash` 是整文件 SHA-1，颜色、切片参数、缩略图任何一处不同，哈希就不同。
- `duplicates.findSimilar()` 是「归一化文件名相同 + 大小相差 ≤2%」，文件名被改成 `at=…v2/final` 就失效，大小变了也失效。

### A.3 技术方案

**指纹算法（对平移 / 旋转 / 等比缩放 / 镜像不变）**

从 3MF 的 `3D/3dmodel.model` 读取网格（复用 `mesh3mf.js` 的 `modelEntries` / `collectMeshes`），做以下特征：

1. **归一化点云**：在三角面上按面积加权采样最多 4000 个表面点 → 去质心 → PCA 对齐主轴 → 除以最大半径归一到单位球。随机数种子取「路径哈希」，保证同一文件每次结果一致。
2. **D2 距离直方图（64 bin）**：随机点对的距离分布。重网格化、改颜色、镜像都不影响。
3. **A3 角度直方图（32 bin）**：随机三点夹角分布，补充 D2 区分不了的形状。
4. **包围盒长宽比（3 个数，降序）**：用于区分「等比缩放」与「非等比拉伸」。
5. **紧凑形状哈希 64 位**：把归一化点云投到 4×4×4 占据栅格，取其中 64 个格子作位图，用于快速分桶。

**相似度打分**

```
score = 1 − ( 0.5·histDist(D2) + 0.2·histDist(A3) + 0.2·(hamming/64) + 0.1·bboxDiff )
```

- `score ≥ 0.92` → 同一模型（标签：改色 / 重切 / 重排）
- `0.80 ≤ score < 0.92` 且包围盒比例不同 → 同一模型的缩放版（标签显示倍数，如「约 1.25×」）
- `0.80 ≤ score < 0.92` → 疑似同款变体（需用户确认）
- `< 0.80` → 不分组

阈值先按上表实现，再用真实库跑一轮校准（见 A.7）。

**计算与缓存（不拖慢扫描）**

- 新文件 `src/core/shapeprint.js`，纯 Node，导出 `shapeSignature(filePath)`、`similarity(a, b)`、`groupVariants(list, opts)`。
- 指纹单独存 `数据目录/shapeprints.json`：`{ version, items: { [模型id]: { h, a, b, g, faces, srcHash, updatedAt } } }`，以 `srcHash`（文件内容哈希）判断是否需要重算。**不写进 library.json**，避免库文件膨胀。
- 不在扫描主流程里同步算。扫描结束后由后台任务补算（并发 1，空闲时跑，可暂停），与现有 `backfillFilamentColors` 的「只补缺、幂等、只写一次」约定一致。
- 体量保护：文件 > 100MB、面数 > 200 万、解析超过 8 秒 → 跳过并记为「未计算」。
- 匹配时先用 64 位紧凑哈希的前 16 位分桶，只在同桶与相邻桶内两两比较；万级库可在秒级完成。

### A.4 数据与契约变更

- 记录新增可更新字段（加入 `library.UPDATABLE_FIELDS`）：`variantGroup`、`variantRole`（`same` / `scaled` / `maybe`）。与现有 `similarGroup` 一样由 `annotate` 风格的函数整体重算，先清空再写。
- 新智能视图：`smart=variants`（`library.matchSmart` 增加分支，`smartCounts` 自动跟随）。
- 设置：`settings.scan.shapePrint`（默认 `true`）、`settings.scan.shapePrintThreshold`（默认 0.80）。
- 新 IPC：

| 方法 | 入参 | 返回 |
|---|---|---|
| `shapePrintStatus` | — | `{ total, done, skipped, running }` |
| `shapePrintRun` | `{ force? }` | 扫描报告式 `{ scheduled, skipped }` |
| `shapePrintStop` | — | `{ ok }` |
| `variantsOf` | `id` | `{ role, score, members: [{ id, score, role, scale }] }` |

### A.5 界面

- 「重复文件」视图改为三个标签：**完全重复 / 疑似重复 / 同款变体**。前两个保持现状，第三个新增。
- 变体组卡片：并排缩略图 + 关系标签（「改色」「约 1.25×」「疑似变体 · 相似度 87%」）。
- 详情抽屉新增「同款变体 (N)」小节，样式沿用现有「相关重复」区块（`.detail-dup-nav`）。
- 设置页「扫描」里加开关与阈值滑块。

### A.6 测试与验收

- 合成网格单测：立方体 平移 / 旋转 / 镜像 / 2 倍缩放 / 重排顶点顺序 → 全部同组；立方体 vs 圆柱体 vs 圆环 → 不同组；立方体挖小孔 → 落入「疑似」区间。
- 真实样本：工作区里现成的拓竹 / Orca 样本，至少验证「同文件改颜色重切后同组」。
- 性能验收：1000 个模型首次全量计算给出耗时；重复运行 100% 命中缓存不重算。
- 探针：`tools/probe-shapeprint.js` 走查标签切换与详情小节。

### A.7 风险与边界

- 阈值是经验值，**必须用真实库校准后再定**，计划里留一轮「校准 + 调参」。
- 对称性强的简单模型（球、立方体）容易互相误判，因此规则是「几何相似只作提示，不自动合并」，合并动作交给 C 且需用户确认。
- 不做：非等比拉伸的精确识别、CAD 级相似、基于 AI 的embedding。

## B · 损坏 3MF 隔离区

### B.1 目标与用户故事

> 扫描报告里写「3 个文件解析失败」，然后就没有然后了。我不知道是哪 3 个、为什么坏、能不能救。我想要一个地方把坏文件单独列出来，能重试、能修复、能挪走，而不是散落在库里当占位图。

### B.2 现状

- `scanner.js` 解析失败会把原因写进 `record.parseError`，文件仍以占位缩略图出现在正常网格里。
- 失败明细只在一次性的扫描报告 `report.files[].action === 'failed'` 里，关掉就没了。
- 没有错误分类，也没有任何修复 / 隔离动作。

### B.3 技术方案

**1. 错误分类**（新函数 `classifyParseError(message, filePath)`，放 `src/core/model3mf.js` 或新文件 `quarantine.js`）

| 类型 key | 触发条件 | 可修复 |
|---|---|---|
| `not-3mf` | 不是 zip / 纯文本改后缀 | 否 |
| `truncated` | zip 中央目录读不到、文件被截断 | 尝试 |
| `bad-crc` | 条目 CRC 校验失败 | 尝试 |
| `missing-core` | 缺 `[Content_Types].xml` 或 `_rels/.rels` | 是 |
| `no-model` | 没有 `3D/3dmodel.model` | 否 |
| `too-large` | 超过解压上限 | 否（提示） |
| `timeout` | 解析超时 | 重试 |

结果写进 `record.parseErrorKind`，`parseError` 保留原文。

**2. 修复策略**（`repair3mf(filePath, { mode })`，输出到**新文件** `<原名>.repaired.3mf`，绝不覆盖原文件）

- `missing-core`：注入标准 `[Content_Types].xml` 与 `_rels/.rels` 后重打包。
- `bad-crc` / `truncated`：逐个读本地文件头，能完整读出的条目重新打包；读不出的条目跳过并在报告里列明。
- 修复后立刻用 `parse3mf` 验证；通过才提示用户「已生成修复版，是否替换原文件」。
- 替换 = 原文件先移入隔离文件夹备份，再改名。全程可回退。

**3. 隔离文件夹**

- 默认 `数据目录/quarantine/`，设置页可改。
- 文件移入后记录 `status: 'quarantined'`、`quarantinedAt`，`path` 更新为新位置。
- `scanner._selfDirs` 加入隔离目录，**扫描器不扫描它**，也不会把这些记录标成 missing。

**4. 状态与视图**

- `library.query()`：`quarantined` 与 `missing` 同等对待——不出现在普通视图，只有维护视图里可见。
- 新智能视图 `smart=broken`（解析失败且未隔离）与 `smart=quarantined`（已隔离）。

### B.4 数据与契约变更

- 记录新增字段：`parseErrorKind`、`quarantinedAt`。`status` 增加 `quarantined` 取值（`library` 里所有 `status === 'missing'` 的判断处逐一审查并补上）。
- 设置：`settings.quarantine.dir`、`settings.quarantine.enabled`（默认 `true`）。
- 新 IPC：

| 方法 | 入参 | 返回 |
|---|---|---|
| `brokenList` | — | `{ items: [{ id, name, path, size, kind, message, mtime, repairable }], summary }` |
| `brokenRetry` | `ids` | `{ ok, still: [...] }`（重新解析，成功则清除错误标记） |
| `brokenRepair` | `id, { replace?: boolean }` | `{ ok, outPath, skipped: [...], replaced }` |
| `brokenQuarantine` | `ids` | `{ ok, failed }` |
| `brokenRestore` | `ids` | `{ ok, failed }`（从隔离移回原目录并恢复状态） |
| `brokenTrash` | `ids` | 复用现有 `trash` 流程，返回释放字节数 |

### B.5 界面

- 新视图文件 `src/renderer/js/views/quarantine.js`，入口放在侧栏「维护」分组（与「重复文件」「失效文件」并列），侧栏显示坏文件数量徽标。
- 列表行：缩略图 / 文件名 / 错误类型（人话，如「文件不完整，可能是下载中断」）/ 大小 / 修改时间 / 可执行按钮。
- 全选 + 批量操作栏：**重试解析 / 尝试修复 / 移入隔离区 / 移入回收站 / 移出索引**。
- 修复结果对话框：成功条目数、跳过条目、「是否用修复版替换原文件」二次确认。
- 扫描结束 toast：「N 个文件解析失败 → 查看」，点击直达该视图。

### B.6 测试与验收

- 合成坏样本各一份：纯文本改后缀、截断一半、破坏 CRC、删掉 `[Content_Types].xml`、删掉 3dmodel.model。
- 断言：分类正确；可修复的两类修复后 `parse3mf` 成功；**原文件哈希在修复前后不变**（除非用户确认替换）；隔离后不出现在普通视图、不被判 missing；恢复后回到原状态。
- 回收站失败时（如网络盘）给出中文原因，索引不被误删。

### B.7 风险与边界

- 「修复」是尽力而为，UI 文案必须如实写「尝试修复」，不能承诺一定成功。
- 不做：从网上重新下载原模型、修复网格几何本身。

## C · 重复模型智能合并

### C.1 目标与用户故事

> 我库里同一个模型存了 4 份，占 1.2 GB。我想要一个按钮：留一份最好的，其余的标成它的「别名」，文件进回收站，并告诉我腾出了多少空间。但我不希望丢失另外几份上的备注、打印记录。

### C.2 现状

- `trash` IPC：`shell.trashItem` 成功后直接 `lib().remove(ids)` —— **索引被删，备注/打印记录随之丢失，也无法撤销**。
- `duplicates.annotate` 只打标记，不提供处理动作。
- `stats()` 的重复计数只认「组内 ≥2」。

### C.3 概念与规则

- **主记录（primary）**：一组里保留的那一条，正常出现在网格、搜索、统计里。
- **别名（alias）**：组内其余记录。降为别名后：
  - 从普通网格、搜索、轮盘、成本汇总、统计里**隐藏**；
  - 作为「副本」列在主记录详情抽屉里；
  - 文件**可选**移入回收站。移入后记录保留为**存根**（`aliasState: 'trashed'`），保留路径、大小、备注，用于显示「已进回收站 · 释放 X」。
- **分组来源**
  - 完全重复（`hash` 相同）：默认全选，可一键处理。
  - 疑似重复 / 同款变体（来自 `findSimilar` / A）：标为「建议合并」，**默认不勾选**，需逐组确认。
- **主记录自动推荐**（打分，可手动改选）

| 条件 | 加分 |
|---|---|
| 有内嵌缩略图 | +3 |
| 元数据更完整（标题 / 作者 / 来源链接 / 重量，每项） | +1 / 项 |
| 打印次数多 | +2 × min(打印次数, 2) |
| 已收藏、有备注、有人工分类 | +2 / 项 |
| 文件在监控目录内且路径最短 | +1 |
| 文件状态正常（非 missing / broken） | 必须，否则不参与 |

  同分取 `createdAt` 最早的一条。

### C.4 技术方案

**新增 `src/core/merge.js`**（纯 Node）

- `previewGroups(library, { kinds: ['exact', 'similar', 'variant'] })` → 每组给出成员、推荐主记录、各成员打分、可释放字节数。
- `scoreMember(rec)` → 上表打分。
- `applyMerge(store, { keep: { [groupId]: primaryId }, trash: true })`：
  1. 校验每个 `primaryId` 属于对应组，否则抛中文错误。
  2. 对每个别名：`aliasOf = primaryId`、`aliasState = 'pending'`。
  3. 逐个 `shell.trashItem`；成功 → `aliasState = 'trashed'`；失败 → 回滚该条为 `aliasOf = null` 并计入 `failed`，**不中断其余**。
  4. 一次 `updateLibrary` 落盘。
  5. 返回 `{ merged, trashed, freedBytes, failed }`。
- **撤销**：文件已在回收站，无法可靠地程序化还原（Windows 回收站恢复没有稳定接口）。因此撤销的语义是「解除别名关系并恢复为独立记录」；如果文件已不在原路径，记录显示为 missing 并提示「可从回收站手动还原后重新扫描」。这一点必须在确认对话框里写明，不能含糊。
- `trash: false` 时只降级为别名不动文件（适合想保留多份但不想在网格里看到的情况）。

**对现有代码的改动点**

- `library.query()`：`aliasOf` 非空且 `aliasState !== null` 的记录默认过滤（除非 `Q.includeAliases`）。
- `stats()` / `smartCounts()` / `roulette()`：同样排除别名。
- `scanner`：别名存根的文件消失时不要标 missing（`aliasState === 'trashed'` 直接跳过）。
- `duplicates.annotate()`：别名不再计入重复组，处理后组自动消失。
- 详情抽屉「副本」小节点进去时用 `Q.includeAliases` 取。

### C.5 数据与契约

- 记录新增字段：`aliasOf`、`aliasState`（`pending` / `trashed`）、`aliasAt`。
- 新 IPC：

| 方法 | 入参 | 返回 |
|---|---|---|
| `dupMergePreview` | `{ kinds? }` | `{ groups: [...], totalGroups, freedBytes }` |
| `dupMergeApply` | `{ keep, trash }` | `{ merged, trashed, freedBytes, failed }` |
| `dupAliases` | `id` | `{ items: [...] }` |
| `aliasDetach` | `ids` | `{ ok }`（解除别名） |
| `aliasForget` | `ids` | `{ ok }`（存根移出索引，需确认） |

### C.6 界面

- 「重复文件」视图顶部加汇总条：「完全重复 N 组 · 可释放 X GB · [一键处理完全重复]」。
- 每组一张卡：成员缩略图，单选框选主记录（默认选推荐项），旁边显示打分理由（「有缩略图 · 打印过 3 次」）。
- 底部主按钮「合并并移入回收站」，次要按钮「只标为别名，不动文件」。
- 确认对话框列出：将处理的组数、文件数、预计释放空间、以及撤销说明。
- 完成后 toast：「已合并 N 组，释放 X」。
- 详情抽屉新增「副本 (N)」小节，可单独解除某个别名。

### C.7 测试与验收

- 打分规则单测（每条规则一个用例 + 同分决胜）。
- 合并后：别名不出现在 `query()` 默认结果、不计入 `stats()`、不进 `roulette()`；主记录详情能列出别名。
- 回收站部分失败：成功的保持 `trashed`，失败的恢复为独立记录，返回值如实分开。
- 快照 + 撤销：解除别名后记录恢复可见。
- 释放字节数 = 实际进回收站的文件大小之和（mock `trashItem` 验证）。
- 探针：`tools/probe-merge.js`，用隔离数据目录走通「预览 → 合并 → toast」。

### C.8 风险与边界

- 最大风险是误删：靠「完全重复默认全选、其余默认不选、预览 + 二次确认、走回收站、存根保留」五层保护。
- 同一盘上 NTFS 硬链接的文件，进回收站不一定真的释放空间；释放数字按文件大小估算，文案写「约」。
- 不做：自动合并（无需确认）、跨设备去重、云端去重。

## D · 耗材库存：剩余量 / 低库存提醒 / 采购清单

### D.1 目标与用户故事

> 打到一半发现料不够了。我希望软件知道每卷料还剩多少，快用完时提醒我，并能一键生成要买的清单。

### D.2 现状

- `filaments.json` 的每条耗材已有：品牌、名称、类型、颜色、单价、图片、标签、参数。
- `receipts.js` 有每次打印的重量与耗时；`cost.js` 能算出一次打印各耗材的克数。
- 两者之间没有打通：打印完不会扣库存，耗材也没有「剩余量」概念。

### D.3 数据模型

耗材记录新增字段（`normalizeFilament` 补默认值，老数据迁移）：

| 字段 | 含义 | 默认 |
|---|---|---|
| `stockG` | 当前剩余克数；`null` 表示「不管理库存」 | `null` |
| `fullG` | 一整卷克数 | `1000` |
| `lowG` | 低库存阈值（克） | `fullG × 10%` |
| `spools` | 未开封的备用卷数 | `0` |
| `buyUrl` | 购买链接 | `''` |

新文件 `数据目录/stock-log.json`：出入库流水，每条 `{ id, at, filamentId, grams, kind: 'print' | 'manual' | 'open', receiptId?, modelName?, note? }`。

### D.4 技术方案

**扣减**

- 触发点：打印回执落库时（`monitor` 的 job 事件 → `receipts.add` 之后）。这是已有的「终态 → 回执」通道，复用，不新增轮询。
- 扣哪一卷：优先用回执关联模型的 `filamentLinks` / `meta.filamentUsages`（逐耗材克数）；模型没关联耗材时用默认耗材兜底（与 `cost.js` 的兜底口径一致）。
- **幂等**：每条流水带 `receiptId`，同一回执只扣一次。
- 回执后来才关联上模型（`receiptsLinkModel` / `receiptsAutoLink`）：补一笔扣减，流水备注「补记」。
- 扣到负数时钳到 0，并记一条「库存数据可能不准，建议称重」的提醒。

**手动调整**

- 「称重后剩余 ___ g」直接写入；「+1 卷」把 `stockG += fullG`、`spools` 减 1（若 > 0）。
- 每次手动调整都记流水，可在流水里逐条撤销。

**低库存提醒**

- 扣减后与每次启动时检查：`stockG <= lowG` → 提醒。
- 同一卷耗材一天内只提醒一次（记 `lowNotifiedAt`）。
- 走现有通知通道（系统通知 + 应用内 toast），并遵循「关闭系统通知时 `system=false`」的现有开关。
- 设置开关 `inventory.lowStockNotify`，默认开。

**采购清单**

- 列出所有 `stockG + spools × fullG <= lowG` 的耗材。
- 建议购买量 = `max(1, ceil((fullG − stockG) / fullG))` 卷。
- 输出：界面清单 + 复制为文本 + 导出 CSV（注意逗号与引号转义，UTF-8 BOM 让 Excel 正确显示中文）。
- 每行带「已下单」勾选（本地状态，7 天后自动清除）和购买链接。

### D.5 契约与界面

- 新 IPC：`stockAdjust`、`stockLog`、`stockUndo`、`stockLowList`、`stockShoppingExport`。
- 耗材视图（`views/filaments.js`）：每张耗材卡加一条库存进度条（`stockG / fullG`）、剩余克数、备用卷数；低于阈值显示橙色「偏低」徽标。
- 编辑面板加「库存」分组。
- 新标签页「采购清单」，放在耗材视图顶部。
- 设置页「耗材」加低库存提醒开关。

### D.6 测试与验收

- 扣减正确、同一回执幂等、撤销一笔后余额恢复、负数钳到 0 并产生提醒标记。
- 老数据迁移后新字段有默认值，`list()` 输出稳定。
- 清单生成与建议购买量计算；CSV 用 Excel 打开不乱码。
- 不管理库存的耗材（`stockG = null`）不参与任何提醒。

### D.7 风险与边界

- 克数来自切片估算，与实际有出入；界面始终标「估算」，并提供称重校准入口。
- 不做：扫码枪 / RFID 识别、多仓位仓库管理、联网查价格与库存。

## E · 上料方案：按模型颜色分配 AMS / 多材料槽位

### E.1 目标与用户故事

> 这个模型要用 4 种颜色。我 AMS 里有 4 卷料但颜色对不上，每次都要自己琢磨哪根放哪个槽。我希望软件直接告诉我：1 号挤出机用 3 号槽，2 号挤出机颜色差得远建议换料。

### E.2 现状

- 模型侧：`meta.filamentColors`、`meta.filamentTypes`、按零件映射的实际使用槽位（`colors.js` / `model3mf.js` 的 `colorPairs`）。
- 打印机侧：`printers.js` 的快照里拓竹机型有 `materials: [{ slot, type, vendor, color, active }]`，来自 AMS；快造 U1 有 4 个工具头。
- 两边都没有被拿来做过匹配。

### E.3 技术方案

**颜色距离**：RGB → CIELAB → ΔE76（实现简单、足够区分「同色 / 近似 / 不同」；ΔE2000 作为可选精度提升，首版不做）。阈值：ΔE ≤ 6 匹配；6–20 近似；> 20 不匹配。

**槽位分配**：这是一个小型指派问题（挤出机数 ≤ 16，槽位数 ≤ 16）。用匈牙利算法求总色差最小解；实现放在 `src/core/loadplan.js`，纯函数、好测。

**三种模式**

| 模式 | 输入 | 输出 |
|---|---|---|
| 用当前料盘 | 模型颜色 + 打印机当前 AMS 快照 | 每个挤出机 → 槽位，标「匹配 / 近似（ΔE 值）/ 不匹配」 |
| 手动摆盘 | 模型颜色 + 用户在界面里填的槽位布局 | 同上；布局可按打印机保存 |
| 重新装料（依赖 D） | 模型颜色 + 当前 AMS + 耗材库存（`stockG > 0`） | 哪些槽不用动、哪些槽换成哪卷库存耗材，换料次数最少 |

**约束与提示**

- 材料冲突：模型要 PLA，槽里是 PETG → 警告「材料不一致，可能影响附着与温度」。
- 颜色数 > 槽位数 → 明确提示「需要中途换料」并列出换料顺序。
- 相同颜色合并：多个挤出机用同色时建议共用一个槽。
- 拓竹 AMS 的「外挂料盘」(tray 255) 作为单独一个虚拟槽位处理。

### E.4 契约与界面

- 新 IPC：`loadPlan(modelId, { printerId?, mode?, layout? })`、`printerLayoutSave(printerId, layout)`。
- 详情抽屉新增「上料方案」小节：
  - 表格：挤出机 | 需要颜色色块 | 材料 | 推荐槽位 | 槽内颜色色块 | ΔE | 状态徽标。
  - 顶部切换「用当前料盘 / 手动摆盘 / 重新装料」。
  - 「复制换料清单」按钮，生成纯文本便于发到手机。
- 打印机离线时回退到「手动摆盘」，并说明「未连接打印机，显示的是上次保存的布局」。
- 设置页「打印机」里可为每台机器保存默认布局。

### E.5 测试与验收

- 颜色距离：同色 ΔE=0；黑 vs 白很大；两种相近蓝落在 6–20。
- 分配：4 色 4 槽最优解正确；颜色数多于槽数时给出换料提示；材料冲突出现警告。
- 重新装料：已有匹配槽不动，换料次数最少。
- 探针：`tools/probe-loadplan.js` 在详情抽屉里走查表格渲染。

### E.6 风险与边界

- 屏幕色块与实物颜色有色差，ΔE 只是近似；文案用「颜色接近」而非「完全一致」。
- **不改写 3MF 里的 `filament_colour`**，也不向打印机下发指令——只给建议，避免改坏切片文件。这两项列为后续可选。

## F · 自然语言搜索

### F.1 目标与用户故事

> 我记得上个月打过一个蓝色的收纳盒，但想不起名字。我希望直接在搜索框里打这句话就能找到。

### F.2 原则

- **完全本地、确定性、可解释**：基于词表与规则，不调用任何在线服务，同样输入永远得到同样结果。
- **不猜**：解析出什么就显示什么。识别不了的词回落为普通关键字搜索，并明确告知。
- 中英文都支持；日/德/西在 H 完成后按同一套词表框架扩展。

### F.3 可识别的意图

| 意图 | 中文示例 | 英文示例 | 映射到查询条件 |
|---|---|---|---|
| 时间范围（按打印时间） | 上个月、本周、最近 7 天、今年 | last month, this week, past 7 days | `printedFrom / printedTo` |
| 时间范围（按入库时间） | 最近添加的 | recently added | `createdFrom / createdTo` |
| 颜色 | 蓝色、蓝的、天蓝 | blue, dark blue | `colorHues: [220]`（±容差） |
| 物品类词 | 收纳盒、支架、摆件、测试件 | holder, box, figure, benchy | `keyword`（直接复用自动分类词库） |
| 打印状态 | 打印过的、没打印的 | printed, unprinted | `printStatuses` |
| 收藏 / 评分 | 收藏的、五星 | favorites, 5 stars | `favoritesOnly / ratingMin` |
| 分类 / 标签 | 分类是工具的、带「送礼」标签 | in Tools, tagged gift | `categoryId / tagIds`（模糊匹配名称） |
| 作者 | 拓竹官方的、某某设计的 | by cocoon | `author` |
| 材质 | PLA 的、PETG | PLA, PETG | `filamentTypes` |
| 颜色数量 | 四色的、多色 | 4 colors, multicolor | `minColors / colorsCount` |
| 文件大小 | 大于 50MB、小于 10MB | bigger than 50MB | `sizeMin / sizeMax` |
| 重复 / 失效 | 有重复的、失效的 | duplicates, missing | `smart` |

### F.4 技术方案

**新文件 `src/core/nlquery.js`**（纯函数，无副作用）

- `parseNL(text, { lang, categories, tags })` → `{ query, chips: [{ type, label, value }], leftover }`。
- 分词：中文按规则切（时间词 + 颜色词 + 类词 + 修饰词），英文按空格 + 短语表。
- 词表数据与语言绑定，放 `src/core/nlquery-lexicon-zh.js` / `-en.js`，后续语言各加一份。
- 颜色词 → 色相区间表（约 24 个基本色 + 明暗修饰）。
- 「现在」的时间由调用方注入（便于测试固定时钟）。

**查询层扩展**（`library.query()`，这些是通用筛选，将来高级筛选面板也能用）

新增可选参数：`printedFrom / printedTo`、`createdFrom / createdTo`、`colorHues`、`filamentTypes`、`colorsCount / minColors`、`sizeMin / sizeMax`、`author`。全部为「不传则不过滤」，保持向后兼容。

颜色匹配：遍历 `meta.filamentColors` 转 HSL，任一颜色色相落在区间内即命中。

**解析结果的呈现**

- 搜索框下方出现一排可单独删除的条件 chip：「已打印 ×」「蓝色 ×」「类词：收纳盒 ×」「时间：上个月 ×」。
- 没识别出任何意图时，chip 区显示「按关键字搜索：…」。
- 用户手动删光所有 chip = 清空搜索。

### F.5 界面与入口

- 搜索框获得焦点时右侧出现「自然语言」小图标提示可用。
- `Ctrl+K` / `Ctrl+F` 聚焦搜索框（快捷键注册表在 H 建立；若 F 先做，则先建最小版注册表）。
- 设置页开关 `search.naturalLanguage`，默认开；关闭后退回纯关键字。

### F.6 测试与验收

- 词表驱动的用例表：中英各 ≥ 40 句，每句断言解析出的 query 对象与 chip 列表。
- 关键回归：解析后的 query 交给 `library.query()` 返回的结果与手工筛选一致（例如造 30 条记录，验证「上个月打印的蓝色收纳盒」只命中同时满足三个条件的那条）。
- 无法识别的句子不报错、不乱筛。
- 探针：`tools/probe-nlquery.js` 输入示例句子并断言 chip 文案。

### F.7 风险与边界

- 规则引擎覆盖不了口语化表达；接受这个上限，靠 chip 让用户一眼看出理解对不对。
- 首版不做在线大模型解析；将来如果要接，必须作为可选开关并明确告知哪些文字会离开本机。

## G · 以图搜图

### G.1 目标与用户故事

> 我看到别人打印的一个东西，想找自己库里有没有。直接把图片拖进来，就能看到相似的模型。

### G.2 现状

- `thumbs.js` 把缩略图缓存在 `数据目录/thumbs/<sha1(path).slice(0,24)>.png|jpg`；无内嵌图的是 `.svg` 占位图。
- 没有任何图像特征。

### G.3 技术方案

**哈希算法**：dHash（差值哈希），每张图 64 位。缩略图缩到 9×8 灰度，相邻像素比较得 64 位。对缩放、轻微裁剪、压缩 artifacts 稳健，计算极快。

**图像解码**：核心模块保持不依赖 Electron。`src/core/imghash.js` 导出纯计算函数 `dhash(grayMatrix)`；解码由调用方注入 `decode(buffer) → { width, height, data }`。Electron 侧在 `electron/services.js` 用 `nativeImage` 实现解码并缩放（`nativeImage.createFromBuffer(buf).resize(9, 8)`），再取位图。

**建立索引**

- 存 `数据目录/img-hash.json`：`{ version, items: { [模型id]: { d: '16位hex', src: 'embedded', updatedAt } } }`。
- 触发：缩略图生成 / 重生成之后入队补算（与 A 的后台补算共用同一个「空闲后台任务」调度器，这个调度器在 A 里建好；G 若先做则先建）。
- 占位 `.svg` 不参与。

**查询**

- 入口：卡片菜单「找相似」、详情抽屉按钮、把图片拖到窗口 / 点击上传。
- 对查询图算 dHash，与全部条目做汉明距离；1 万条 × 64 位 popcount 是毫秒级，不需要索引。
- 返回距离 ≤ 10 的前 20 个，按距离升序；> 10 视为不相似。
- 距离 0–3 标「很可能相同」；4–10 标「相似」。

**与 A 互补**：缩略图相同但几何不同（同图不同模型）→ A 能排除；几何相同但缩略图不同（重渲染）→ A 能补上。结果面板里同时显示「几何相似」标记（若 A 已算出）。

### G.4 契约与界面

- 新 IPC：`imgHashStatus`、`imgHashRun({ force? })`、`imgFindSimilar({ id? , dataUrl? , filePath? })`、`imgHashStop`。
- 结果以模态画廊展示（复用 `components/modal.js`），网格与卡片同款，可按距离排序，点击进入详情。
- 上传的图片只在内存里计算，不落盘。

### G.5 测试与验收

- 纯函数：同一张图缩放 / 轻微裁剪 / 重存 JPEG 后汉明距离 ≤ 6；两张完全不同的图距离 > 20。
- 索引：只处理有内嵌图的记录；重复运行不重算；缩略图重生成后哈希更新。
- 探针：`tools/probe-imghash.js` 对某条记录调用找相似并断言自身排第一、距离为 0。

### G.6 风险与边界

- MakerWorld 同一模型的缩略图通常完全相同，命中率高；自己重新渲染的缩略图命中率低——这是算法上限，文案要写「按缩略图外观查找」。
- 不做：CLIP 等深度特征、3D 形状检索（那属于 A）。

## H · 多语言与无障碍：日 / 德 / 西 + 快捷键 + 高对比度 + 字体缩放

### H.1 目标与用户故事

> 我的朋友是德国人，英文界面能凑合用，但有德语更顺手。另外我眼睛不太好，希望字能大一点、对比度高一点，常用操作最好有快捷键。

### H.2 多语言

**现状约束（改造前必须处理的地方）**

- `i18n.js` 里语言是两个常量 `ZH` / `EN`，`makerWorldRegionOf()` 用 `lang === EN` 判断国际站。
- `store.js` 的新装默认语言逻辑、`filaments.js` 的「英文不内置耗材」判断、`classify.js` 的 `languageOf()`，都只认 `en-US`。
- 这些地方统一改为 `isZh(lang)` 判断：**非中文一律走国际站、不内置耗材、用非中文默认分类**。

**语言范围**：`ja-JP`、`de-DE`、`es-ES`。三种语言的使用者都应默认 MakerWorld 国际站。

**翻译策略（关键决策）**

- 词条总量约 1811 条 × 3 种语言。此前免费机翻接口配额已耗尽，且机翻质量对 UI 文案不够好。
- 分层处理：
  - **第一层（可见 UI，约 600 条）**：人工逐条翻译，覆盖主界面、设置、详情、耗材、设备、回执、向导、所有按钮与标题。
  - **第二层（错误与提示，约 1200 条）**：逐批翻译；未翻译完之前**回落到英文**，而不是回落到中文。
- `t()` 的查找链改为：`当前语言 → en-US → 原文`。中文以外任何语言都不应出现中文。
- 新增 `tools/i18n-parity.js`：断言每种语言的词条覆盖率达到设定阈值，并在 CI（`selftest`）里跑。
- 默认分类名与自动分类关键词：为每种语言各准备一套分类名 + 约 40 个/分类的本地语言关键词（由我编写，参考各语言社区常用词）。
- 数字 / 日期：按语言用 `Intl.DateTimeFormat` 与 `Intl.NumberFormat`；小数点与千分位跟随语言。

### H.3 快捷键

- 新文件 `src/renderer/js/hotkeys.js`：命令注册表 `{ id, title, defaultKeys, when, run }`，统一监听 `keydown`。
- 内置命令（首版）：

| 命令 | 默认键 |
|---|---|
| 聚焦搜索框 | `Ctrl+F` |
| 命令面板 | `Ctrl+K` |
| 设置 | `Ctrl+,` |
| 撤销 | `Ctrl+Z` |
| 切换智能视图 | `1` – `6`（仅未聚焦输入框时） |
| 预览 | `Space` |
| 关闭抽屉 / 弹层 | `Esc` |
| 移入回收站（带确认） | `Delete` |

- 规则：焦点在输入框 / 文本域时一律不触发；冲突检测（两个命令不能占同一组合键）；用户自定义存 `settings.ui.hotkeys`，可「恢复默认」。
- 命令面板（`Ctrl+K`）：一个输入框 + 模糊匹配的命令列表，顺带提供「跳到某分类」「切换视图」「立即扫描」等动作。
- 设置页新增「快捷键」页，列出全部命令并支持点击后按键改绑。

### H.4 高对比度

- 新主题 `data-theme="hc"`：基于现有 CSS 变量体系覆盖一组高对比配色（正文对比度 ≥ 7:1，边界 1px 实线，焦点环 2px）。
- 状态不只靠颜色表达：未打印 / 已打印 / 失效等补图标或文字标签。
- 遵循 WCAG 2.1 AA；用 axe-core 在截图探针里跑一遍，断言无 serious / critical 违规。
- 同时尊重系统 `prefers-contrast: more`，首次启动时若系统开启了高对比则默认启用。
- `prefers-reduced-motion`：关闭现有动效（`components/motion.js`），并在设置里给手动开关。

### H.5 字体缩放

- 方案：`webContents.setZoomFactor(scale)`，由设置项 `ui.fontScale`（85% / 100% / 115% / 130% / 150%）驱动。
- 选它的原因：Electron 原生支持，所有 px 布局一起等比放大，不需要把全部 CSS 改成 rem，回归风险最低。
- 配套：窗口最小尺寸随缩放调整；用截图探针在 150% 下走查主要页面，确认没有溢出、截断、重叠。
- 启动时从 localStorage 读回缩放，首帧就生效，避免闪烁（做法与语言首帧一致）。

### H.6 测试与验收

- `i18n-parity`：三种语言第一层 100% 覆盖；全量达到设定阈值。
- 探针 `tools/probe-i18n.js` 参数化语言：`ja-JP` / `de-DE` / `es-ES` 各跑一遍，断言标题、搜索占位、空状态、按钮文案均为目标语言，且页面内不残留中文。
- 快捷键探针：模拟按键，断言命令触发；焦点在输入框时不触发。
- 150% 缩放探针：截图 + 断言关键元素矩形不超出视口。
- 高对比度探针：axe 扫描 0 个严重违规。

### H.7 风险与边界

- 工作量主要是翻译，且不可压缩；建议拆成「框架改造 + 日语」先行，再逐个加德语、西语，每个语言单独验收。
- 德语单词较长，按钮和标签可能溢出：需要一轮「长文本走查」，必要时允许换行或加宽。
- 不做：右到左语言（阿拉伯语 / 希伯来语）、语音朗读。

## I · 打印周报 / 成就卡片 + 模型护照

### I.1 目标与用户故事

> 忙了一个月，想知道自己到底打了多少东西、用了多少料、花了多少钱，最好能生成一张图发朋友圈。另外我卖过打印件，想知道哪些模型的许可允许商用。

### I.2 数据来源（全部已有，不新增采集）

| 数据 | 来源 |
|---|---|
| 打印次数、成功/失败、耗时 | `receipts.js` 的回执 |
| 克数与成本 | 回执的 `weightG` + `cost.js` |
| 按颜色 / 材质消耗 | 回执关联模型的 `filamentUsages` |
| 新增模型数 | `library` 记录的 `createdAt` |
| 设计师、来源、许可 | `meta.designer`、`sourceUrls`、MakerWorld 接口返回的 `license` |

### I.3 周报

**内容**（自然周，周一 0 点到周日 24 点，时区取本机）

- 打印 N 次 · 成功 M 次 · 累计时长 H 小时
- 消耗 X g 耗材 · 约 ¥Y
- 用量最高的 3 种颜色（色块 + 克数）
- 新入库 K 个模型
- 最常打印的 3 个模型（缩略图）
- 与上周对比（↑12% / ↓5%）

**生成与展示**

- 纯函数 `buildWeeklyReport(receipts, models, filaments, { from, to })` 放 `src/core/report.js`，时间区间由调用方注入，方便测试。
- 卡片渲染：一个隐藏的 `BrowserWindow` 加载本地 HTML 模板 → `capturePage()` 导出 PNG（1200×1500）。不引入 canvas 依赖，样式与界面一致。
- 操作：保存 PNG / 复制到剪贴板 / 关闭。图片默认存到用户「图片」目录下的 `PrintShelf` 子文件夹。
- 触发：设置 `report.weeklyEnabled`（默认开）。启动时若距上次展示已跨过一周，弹出周报（可忽略，不打断操作）。设备页与侧栏提供「查看周报」入口，可回看任意一周。

### I.4 成就

**规则（纯函数 `evaluateAchievements(stats)`，规则表数据化，便于以后追加）**

| 成就 | 条件 |
|---|---|
| 第一件作品 | 累计成功打印 ≥ 1 |
| 渐入佳境 / 熟能生巧 / 打印老手 | 累计成功 ≥ 10 / 100 / 500 |
| 七日不断 | 连续 7 天每天都有成功打印 |
| 五彩缤纷 | 单周用到 ≥ 5 种颜色 |
| 一公斤俱乐部 | 累计消耗 ≥ 1000 g |
| 收纳大师 | 「功能件」类打印 ≥ 10 次 |
| 调参狂人 | 「测试校准」类打印 ≥ 10 次 |

- 存 `数据目录/achievements.json`：`{ [key]: { unlockedAt } }`。
- 评估时机：每次回执落库后 + 每次启动。解锁时弹一条 toast，不重复弹。
- 成就页：已解锁 / 未解锁两栏，未解锁只显示名称与条件，不剧透具体数字以外的内容。

### I.5 模型护照

**记录字段**（新增 `passport` 对象，加入可更新字段）

```
passport: {
  designer: '',          // 设计师
  license: '',           // 规范化后的许可 key，如 'CC-BY-4.0' / 'CC-BY-NC-SA-4.0' / 'GPL-3.0' / 'unknown'
  licenseName: '',       // 原始文本
  licenseUrl: '',
  sourceSite: '',        // makerworld | printables | thingiverse | other
  attribution: '',       // 署名要求原文
  commercial: null       // true / false / null（未知）
}
```

**自动填充**

- `designer` ← `meta.designer`；`sourceSite` / 链接 ← 现有 `sourceUrls` 解析结果。
- 许可：MakerWorld 的 `design-service/model` 接口在反查作品页时一并返回许可信息，`source-urls.js` 里解析时顺手存下（**不增加额外请求**）。其余站点首版留给用户手填。
- 许可规范化表：CC 系列拆出「署名 / 非商用 / 相同方式共享」三个属性，从而得出 `commercial`。
- 只有用户打开过来源链接或触发过反查的模型才有自动数据；其余显示「未获取」，并提供「获取许可」按钮（走现有反查接口）。

**展示**

- 详情抽屉新增「模型护照」小节：设计师、来源站点图标与链接、许可徽标、三句人话（「需署名」「不可商用」「需以相同许可共享」）。
- 编辑：设计师、许可、署名可手动修改并保存；手动值不会被自动填充覆盖（加 `passport.manual = true` 标记）。
- 列表视图可加「许可」列；`library.query()` 新增 `licenseCommercial: true|false` 筛选。
- 「可商用模型」智能视图（`smart=commercial`）。
- 设置页「数据」提供「导出模型护照 CSV」，方便摆摊 / 网店备查。

### I.6 测试与验收

- 周报：固定一组回执与模型，断言各项数字与环比；跨周边界（周日 23:59 vs 周一 00:00）用注入时钟验证。
- 卡片：隐藏窗口渲染出非空 PNG，尺寸正确。
- 成就：每条规则正反各一个用例；解锁后不重复；解锁记录持久化。
- 护照：许可字符串规范化（各种写法的 CC-BY-NC 4.0）→ 属性与 `commercial` 正确；手动值不被覆盖；CSV 转义。
- 探针：`tools/probe-report.js`、`tools/probe-passport.js`。

### I.7 风险与边界

- 许可信息来自第三方接口，可能缺失或变更；界面标注「信息来自作品页，请以原作者说明为准」，不构成法律意见。
- 周报里的成本是估算值，卡片上标「约」。
- 不做：分享到社交平台的直接接口（只提供保存图片 / 复制）。

## 附：建议的开发顺序与发版

| 批次 | 内容 | 理由 |
|---|---|---|
| 第 1 批 | B → C | 风险最低、用户收益最直接；C 直接复用 B 的回收站与确认流程 |
| 第 2 批 | A | 给 C 补上「变体」维度；需要一轮真实库校准，单独成批 |
| 第 3 批 | D → E | 耗材数据打通后 E 才完整 |
| 第 4 批 | G → F | G 简单先出成果；F 依赖查询层扩展，工作量较大 |
| 第 5 批 | H | 翻译量大，建议拆成「框架 + 日语」「德语」「西语」三次交付 |
| 第 6 批 | I | 依赖前面的回执与许可数据积累 |

以上只是建议，实际顺序由你指定——你说开发哪个，我就只做哪个。

## 附：每个功能开工时的固定流程

1. 先跑一遍 `npm run selftest` 确认基线全绿。
2. 核心模块（纯 Node）+ 单测先行，测过了再接 IPC 与界面。
3. 界面用隔离数据目录（`PRINTSHELF_DATA_DIR` 指向临时目录）跑截图探针走查，不碰真实库。
4. 补 `tr()` 词条（中英同时）、跑 `check-ipc-contract`、跑全量 `selftest`。
5. 更新 `docs/09`、`docs/18`、README，最后再谈版本号与发布。
