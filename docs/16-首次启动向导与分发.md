## 2. 红框问题：不是「字太长」，是类名对不上

`views/detail.js` 输出的是：

```html
<div class="meta-cell"><span class="meta-k">修改时间</span><span class="meta-v">...</span></div>
<div class="meta-cell meta-wide"><span class="meta-k">完整路径</span><span class="meta-v mono">C:\...</span><button .../></div>
```

而 `styles/views.css` 里只给 `.meta-item / .meta-label / .meta-value` 写了省略号规则。
`.meta-v` 没有 `min-width:0 + overflow:hidden + text-overflow:ellipsis + white-space:nowrap`，
Windows 路径又没有可断行点 → 整行撑破网格，把复制按钮顶到面板外，并被面板边缘裁掉。

修法（`styles/views.css`）：

1. 补齐 `.meta-cell / .meta-k / .meta-v / .meta-wide` 四个类的规则（与旧类名共存，不破坏别处）。
2. `grid-template-columns: repeat(auto-fit, minmax(132px, 1fr))`：宽时两列，窄时自动一列，不再硬套 `1fr 1fr`。
3. 完整路径改成 `.meta-path` 两栏网格（值 `minmax(0,1fr)` + 按钮 `auto`），值可省略、按钮永远在面板内。
4. `.detail-body` 加 `overflow-x: hidden`，任何未来新增的长内容都只会本行省略，不会撑出横向滚动条。

验证：`tools/probe-detail-overflow.js` 在 1480 / 1180 / 1024 / 900 四种窗口宽度下断言
`scrollWidth <= clientWidth`、复制按钮右边界不超过面板、路径带 `title` 提示，全部通过。

## 3. 首次启动向导

### 3.1 何时出现（不打扰老用户）

```
settings.onboard.done === true        → 不弹
模型库总数 > 0                        → 静默写 done（老用户升级迁移），不弹
其余（空库 + 未完成）                 → 弹
```

「稍后再说」也会写 `done`，避免每次启动都拦；设置 → 数据管理提供「重新运行初始化向导」。

### 3.2 三步流程

| 步骤 | 内容 | 关键行为 |
| --- | --- | --- |
| 1 欢迎 | 一张「配置清单」：1 个必做（选择模型文件夹）+ 2 个可选（切片软件、默认耗材） | 明确「不配可选项也能正常管理模型」，并说明数据只留在本机、不上传、不注册 |
| 2 模型文件夹 | 推荐选择一个专门放 3MF 的文件夹；整盘扫描和扫描深度收进 `<details>` 高级项 | 默认不勾选任何盘；选中后显示「已选择 N 个位置」，未选时按钮为「先选一个位置」并禁用；深度 快速4 / 标准8 / 深入12 |
| 3 扫描 | 进度条 + 当前路径 + 计数 → 结果「N 个模型，本次新增 X」 | 可取消；完成后结果页列出「接下来（可跳过）」：切片软件、耗材成本、先逛逛；「进入模型库」接三步引导 |

推荐路径：`选择文件夹 → folderAdd() → scanStart()`，只扫用户指定的文件夹；
整盘扫描作为高级选项保留，把盘根写入监控目录后再扫描。扫描深度写 `settings.scan.maxDepth`，下次增量扫描继续沿用。
扫描完成事件到达后先拉一次最新 `stats()` 再渲染，避免旧计数导致「没有找到 3MF 文件」闪烁。

**中英切换**：向导右上角有「中 / EN」分段开关，和主界面语言按钮共用 `ui.language`。切换会触发整页 reload（模块顶层词条才能一起切换），向导用 `sessionStorage` 暂存当前步骤、已选目录和扫描结果，reload 后恢复到同一步；扫描进行中开关禁用，避免丢结果。

### 3.3 设置结构（`src/core/constants.js`）

```js
onboard: {
  done: false,
  at: 0,
  depth: 'standard',   // fast | standard | deep
  skipped: false,      // 区分「跳过」与「走完」
  guideDone: false,
  migrated: false,     // 老用户静默标记
}
```

### 3.4 新手引导

库里有模型时才启动，三步聚光灯：`#btn-quick-add` → `#nav-library` → 第一张 `.card[data-id]`。
目标元素不存在时自动降级为居中气泡，不会卡住；Esc / 跳过都写 `guideDone`。

## 4. 分发打包

机器上不依赖 electron-builder：绿色版直接复制 `node_modules/electron/dist`，
`electron.exe` 改名 `3MF模型管理器.exe`，应用代码放 `resources/app/`；安装包用本地缓存的 NSIS 编译。

```bash
npm run build        # 绿色版目录 + 便携 zip
npm run setup        # 用已有绿色版目录生成安装包
npm run setup:rebuild # 先 build-all 再生成安装包（发布用）
```

产物（1.2.2 实测）：

| 产物 | 路径 | 体积 |
| --- | --- | --- |
| 绿色版 | `dist/3MF模型管理器-1.2.2-win-x64/` | ≈273 MB |
| 便携 zip | `dist/3MF模型管理器-1.2.2-portable.zip` | ≈116 MB |
| 安装包 | `dist/3MF模型管理器-1.2.2-setup.exe` | ≈83 MB |

> 发布到 GitHub 时使用 ASCII 文件名：`3MF-Model-Manager-1.2.2-portable.zip`、`3MF-Model-Manager-1.2.2-setup.exe`。
> `build-portable.js` 会跳过 `node_modules/electron/dist/data` 与 `debug.log`，避免把开发机模型库/缩略图打进发布包。

目录里自带 `一键安装.bat`（复制到 `%LOCALAPPDATA%\Programs\PrintShelf` + 桌面/开始菜单快捷方式 + 自动启动）
与 `卸载 3MF模型管理器.bat`（删程序、保留 data 并提示）。

### 4.1 数据目录（绿色版关键）

打包版的数据落在 **exe 同级的 `data/`**：拷走整个文件夹就带走了全部索引与缩略图。
若 exe 所在目录不可写（例如装进 Program Files），自动退回 `%APPDATA%\PrintShelf\data`。

逻辑在 `electron/main.js` 启动最前面（`app.isPackaged` 时设置 `PRINTSHELF_DATA_DIR`），
必须早于 `require('./services')`。

### 4.2 打包后才暴露的两个真实 bug

1. **命令行参数错位**：`process.argv.slice(2)` 在打包版会吞掉第一个参数（`--smoke` / `--capture` 全失效）。
   根因：打包版 `process.defaultApp` 是 `undefined` 而不是 `false`，写成 `=== false ? 1 : 2` 判断反了。
   现改为 `process.argv.slice(process.defaultApp ? 2 : 1)`。
2. **转换 worker 不在包里**：`tools/u1/convert-worker.js` 被「打包排除 tools/」规则漏掉，
   绿色版的「普通 3MF → 快造 U1」会直接失败。已把 worker 移到 `src/core/u1-worker.js`，
   随 `src/` 一起打包，从结构上消除隐患。

另外：`ensureSeedData()` 在打包版直接返回，避免把 `resources/app` 当成样本目录写进用户设置。

## 5. 「普通 3MF → 快造 U1」的正确性验证

这条是用户明确点名的重点，已从「遇到样本被删就跳过」改成常驻验证：

- 样本来源优先级：`PRINTSHELF_U1_SAMPLE` → 旧硬编码路径 → `data/library.json` 里体积适中的多色工程。
- `tests/u1-tests.js` 真实端到端现在会跑 14 条断言（本机 76 条全过），包括：
  目标机型 U1、兼容列表只剩 U1、耗材预设合并、四个工具头、结构校验、源文件未被修改、二次命中缓存。
- `tools/u1/verify-lib.js` 是命令行与单测**共用**的判定，10 项硬指标：

```text
zipOk / modelXml / printerModel / printerSettingsId / printableArea /
printableHeight / compatOnlyU1 / noBambuResidue / geometryKept / sourceUnchanged
```

本机实测（Bambu A2L 多色 10.5 MB → U1）：

| 指标 | 结果 |
| --- | --- |
| 机型 | Bambu Lab A2L 0.4 nozzle → **Snapmaker U1 (0.4 nozzle)** |
| 打印面积 | **270.5×271**（U1 标准床），高度 270.05 |
| 兼容列表 | 仅 `Snapmaker U1 (0.4 nozzle)`，无 Bambu 残留 |
| 几何 | 对象数 21 → 21（未丢件） |
| 颜色 | 2 色保留 |
| 源文件 | 大小与 mtime 未变 |
| 耗时 | ≈2.2 s |

**打包版同样验证过**：用绿色版 `PrintShelf.exe` 跑同一个模型，产物 10 项校验全过。

## 7. 已知限制

1. 绿色版 exe 的图标是 Electron 默认图标（没有 rcedit，无法在无网络环境写入 exe 资源）；
   窗口与快捷方式用的是 `resources/app.ico`。
2. 便携 zip 首次运行会被 Windows SmartScreen 提示「未知发布者」——没有代码签名证书，属预期。
3. 单实例锁：同时运行两份绿色版时，第二份会静默退出（标准 Electron 行为）。
4. 整盘扫描耗时取决于文件量；向导默认不勾任何盘，推荐只选一个模型文件夹，只有模型分散在整块盘里时才用「高级：按盘扫描」。
5. 耗材预设名失效（例如 `拓竹petg` 在预设里已不存在）时，转换照常完成，但不合并该预设参数，
   产物里只写名字并给出 warning —— 这是设计行为，不阻断转换。
