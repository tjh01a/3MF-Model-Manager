## 1. 目标与验收标准

### 1.1 用户侧目标

1. 应用内提供明确的中英切换按钮，切换后界面立即生效，不需要重启。
2. 英文界面下，MakerWorld 相关链接默认走国际站 `makerworld.com`，不自动跳到 `.com.cn`。
3. 中文界面下保持现有行为：默认中国站 `makerworld.com.cn`，语言段 `/zh`。
4. GitHub 仓库有完整英文 README，外国朋友能独立完成下载、安装、首次扫描和常见问题排查。

### 1.2 验收标准

- 英文界面下，除用户自己填写的标题/备注、模型原名、品牌名外，不再出现中文 UI 文案。
- 中文界面下现有布局、功能、链接行为不回归。
- 语言切换后，侧栏、卡片、详情、设置、弹窗、Toast、错误提示、空状态、引导页全部同步更新。
- 英文界面打开 MakerWorld 链接时，优先使用国际站 URL；只有国际站没有对应作品时才回退中国站，并给出明确提示。
- 老用户的 `library.json`、分类、标签、备注、打印状态、耗材和回执不因升级丢失。
- `README.en.md` 的下载链接、截图、FAQ 与当前版本一致。
- `npm run selftest`、i18n 完整性检查、双语 UI 走查全部通过。

### 2.1 代码与文案规模

- `src/`、`electron/` 中共 **82 个文件**含中文；

### 2.3 现有 MakerWorld 逻辑

当前实现：

| --- | --- |

## 3. 总体设计

### 3.1 语言模型

建议设置项：

```js
settings.ui.language = 'zh-CN' | 'en-US'
```

规则：

- **老用户升级**：没有 `ui.language` 时迁移为 `zh-CN`，避免中文用户突然变英文。
- **全新安装**：读取 `app.getLocale()`；`zh*` 用 `zh-CN`，其余用 `en-US`。
- **切换方式**：设置页「外观 / Language」+ 顶栏快捷按钮；保存到 `settings.json`。
- **不引入第三个 `auto` 状态**：自动判断只发生在首次启动，之后以用户选择为准，避免逻辑复杂。
- 切换语言后更新 `<html lang>` 和 `data-lang`，重启当前视图渲染；主进程读取同一设置，用于通知/错误。

### 3.2 文案组织

建议目录：

```text
src/renderer/locales/
  zh-CN.json
  en-US.json
src/core/i18n.js          // 主进程 / core 共用读取与格式化
src/renderer/js/i18n.js   // 渲染层 t()、data-i18n、日期/复数
```

原则：

- 按命名空间分组：`common.*`、`nav.*`、`card.*`、`detail.*`、`settings.*`、`errors.*`、`onboarding.*`、`devices.*`、`receipts.*`、`filaments.*`、`monitor.*`。
- 渲染层：`t('settings.title')`；静态 HTML 用 `data-i18n` / `data-i18n-title` / `data-i18n-placeholder` / `data-i18n-aria`。
- 主进程：`t('errors.scanFailed', { path })`，通知和原生提示也走同一套。
- 日期/相对时间：用 `Intl.RelativeTimeFormat` / `Intl.DateTimeFormat`，不要手写 `分钟前` / `min ago`。
- 英文复数：用 `Intl.PluralRules('en-US')` 处理 `1 model / 2 models`。
- 缺 key 时开发环境打印警告；生产环境回退到中文，避免空白界面。
- 不翻译：代码注释、内部日志、协议字段、用户数据、模型原名、品牌名、耗材型号（PLA/PETG 等）。

### 3.3 错误与通知

当前大量 core 代码直接 `throw new Error('中文原因')`，这是全面英文化最大的隐性成本。

建议分两层：

1. **新代码/重点路径**：改成稳定错误码 + 参数，例如 `SCAN_PATH_UNREADABLE`、`SLICER_NOT_CONFIGURED`，由 i18n 决定显示语言。
2. **历史错误**：加 `translateLegacyError(message)` 兼容映射；英文界面遇到未登记的中文错误时，显示英文通用句 + 原文折叠，避免把整段中文直接甩给用户。

范围包括：

- IPC 错误 Toast；
- 扫描/切片/耗材/打印机/摄像头/Moonraker/拓竹云端错误；
- 系统通知（打印完成、失败、暂停、断料）；
- 文件选择、确认框、空状态、引导页。

## 4. MakerWorld 链接策略

### 4.1 行为矩阵

| 界面语言 | 站点偏好 | 输入 `makerworld.com` | 输入 `makerworld.com.cn` |
| --- | --- | --- | --- |
| 中文 | 自动/中国站 | 转 `.com.cn`，语言段 `/zh` | 保持 `.com.cn`，语言段 `/zh` |
| 英文 | 自动/国际站 | 保持 `.com`，语言段 `/en` | 优先找国际站对应页；找不到则回退中国站并提示 |
| 任意 | 用户显式选手动站点 | 按用户选择，不被语言覆盖 | 按用户选择 |

建议设置项：

```js
settings.ui.makerWorldRegion = 'auto' | 'cn' | 'global'
```

- `auto`：跟随界面语言；中文 → `cn`，英文 → `global`。
- 老设置 `ui.makerWorldCn` 一次性迁移：
  - 明确设过 `true` → `cn`
  - 明确设过 `false` → `global`
  - 没有设置 → `auto`
- 设置页文案从「优先中国站」改为「MakerWorld 站点：自动 / 中国站 / 国际站」。

### 4.2 URL 存储：从单值升级为双区域

只存一个 `sourceUrl` 无法同时满足中英文用户。建议保留现有字段兼容卡片，同时新增：

```js
model.sourceUrl          // 兼容旧逻辑，保留当前主链接
model.sourceUrls = {
  cn: 'https://makerworld.com.cn/zh/models/1781480',
  global: 'https://makerworld.com/en/models/...'
}
model.sourceRegion = 'cn' | 'global' | null
```

规则：

- 卡片仍优先读 `sourceUrl`，不破坏现有探针和 UI。
- `openExternal` 根据当前语言 + 站点偏好，从 `sourceUrls` 里选目标。
- 没有对应区域时，回退 `sourceUrl`；英文界面弹一次轻提示：`This model is only available on MakerWorld China.`
- 不把“猜出来的域名互换”写成确定值；域名互换只作为最后兜底，避免把 404 当成功。

### 4.3 回填策略

扫描/启动回填时：

1. 3MF 描述里有直接 URL：写入对应区域；如果能从 `DesignModelId` 找到另一区域，再补另一条。
2. 没有直接 URL、有 `DesignModelId`：
   - `DesignRegion=CN`：查 `https://api.bambulab.cn/v1/design-service/model/{id}`
   - 非 CN：查 `https://api.bambulab.com/v1/design-service/model/{id}`
   - 可选：两边都查一次，谁能返回数值 `id` 就写谁。
3. 网络失败/超时：不写空值，不阻断扫描；下次启动再试。
4. 不修改原始 3MF，只写库。

### 4.4 兼容性说明

中国站与国际站是独立模型库，ID 不通用。英文界面“默认国际站”能保证**有国际站链接的模型走国际站**；只有中国站的模型无法凭空生成国际站页面。这个限制必须在 README 和设置页写清楚，不能承诺 100% 都有国际站对应页。

## 5. 翻译范围与优先级

### P0：没有它英文用户无法正常使用

- 启动/首屏、侧栏导航、搜索框、排序/筛选、空状态。
- 卡片：标题占位、状态、来源按钮、色板提示、右键/更多菜单。
- 详情抽屉：文件信息、来源、成本、备注、打印状态、评分。
- 设置页：外观、扫描、切片软件、耗材、打印机、自动分类、数据维护。
- 首次启动向导、添加目录、扫描进度、错误 Toast。
- 文件选择/确认/删除等关键弹窗。

### P1：英文用户会频繁碰到

- 设备管理、打印监控、温度曲线、摄像头、回执、耗材库。
- 重复文件视图、批量操作、拖拽分类提示。
- 系统通知、打印完成/失败/暂停文案。
- 自动分类结果、默认分类名、内置耗材显示名。
- 常见错误：路径不可读、切片软件未配置、打印机连接失败、文件损坏。

### P2：可以二期补

- 模型体检/优化、U1 转换的高级说明。
- 诊断日志、备份恢复细节、开发者文档。
- 非关键 tooltip、帮助长文、更新日志。

### 数据层文案（最容易漏）

| 数据 | 处理建议 |
| --- | --- |
| 默认分类（功能件/摆件装饰/测试校准/备件维修/唱片/绘画） | 首次启动按语言生成英文默认名；老库不改名 |
| 自动分类关键词 | 英文界面增加英文关键词别名；不要直接翻译中文词库导致中文匹配失效 |
| 内置耗材名称 | 品牌名保留；类型/描述可英文化；老数据不强制迁移 |
| 打印回执 | 存稳定状态 + 时间/数值，显示时本地化，不把“打印完成”写死进数据 |
| 打印状态 | 数据里继续存 `unprinted/printed/...`，只翻译显示标签 |

## 6. GitHub 英文说明

### 6.1 README 方案

建议保留中文 README，并新增完整英文版：

```text
README.md          # 简体中文（现有）
README.en.md       # English
```

两个文件顶部都加：

```markdown
[简体中文](README.md) | [English](README.en.md)
```

英文版内容与中文版对齐：

- What it is
- Download / Install
- First scan in 3 steps
- Features
- FAQ（联网、数据目录、卸载、SmartScreen）
- Build from source
- License

> 如果希望 GitHub 默认给外国访客看英文，可把 `README.md` 改为英文、中文移到 `README.zh-CN.md`。这是需要确认的发布策略，不建议未经确认直接改默认首页。

### 6.2 截图与 Release

- 新增 `docs/screenshots/en/00-main.png`、`00-main-dark.png`、`00-color-tooltip.png`，尺寸与中文截图一致（1850×1175）。
- Release Notes 提供中英双语，至少英文部分包含：
  - 版本亮点
  - 安装包/绿色包文件名
  - SmartScreen 说明
  - 数据目录与升级说明
- GitHub About 描述可改为双语，例如：
  `Local 3MF model library for Windows / Windows 本地 3MF 模型库`

## 7. 分阶段实施计划

### 阶段 0：锁定清单（0.5 天）

- 写脚本扫描 `src/`、`electron/` 的字符串字面量和 HTML 文本，区分注释与用户可见文案。
- 产出 `docs/21-国际化文案清单.csv`：文件、位置、中文、建议 key、优先级。
- 确定术语表（模型库、切片软件、耗材、回执、打印状态等）。

### 阶段 1：i18n 基础设施（1～1.5 天）

- 新增 `zh-CN.json` / `en-US.json`、`t()`、`data-i18n`、日期/复数格式化。
- 增加 `ui.language` 默认值、老用户迁移、首次安装语言检测。
- 设置页加语言切换；顶栏加入口。
- 增加 `npm run i18n:check`：key 对齐、缺 key、英文包混入中文检查。

### 阶段 2：渲染层 P0 翻译（2～3 天）

- `index.html`、侧栏、卡片、详情、设置、首次向导、核心弹窗。
- 所有 aria-label / title / placeholder 一并处理。
- 英文布局走查：1480 / 1180 / 860 宽度，按钮不溢出、卡片不截断。

### 阶段 3：主进程、core 错误与通知（2～3 天）

- 重点错误改错误码；历史错误加兼容翻译。
- 打印通知、扫描状态、切片/耗材/设备错误英文化。
- 确认英文界面不会把中文异常堆栈直接弹给用户。

### 阶段 4：MakerWorld 双语链接（1～2 天）

- 新增 `ui.makerWorldRegion` 与 `sourceUrls`。
- 改造 `openExternal`、回填、卡片链接选择。
- 补单元测试：中英文 × 中国站/国际站 × 有无对应链接。
- 真实样本验证：Mega_Lucario / BOTW / 纯国际站模型。

### 阶段 5：GitHub 英文文档（0.5～1 天）

- `README.en.md`、语言切换、英文截图、英文 Release Notes。
- 检查所有图片链接、下载链接、版本号。

### 阶段 6：全量回归与发布（1～1.5 天）

- 双语 UI 走查；英文界面中文残留扫描。
- 老库升级、空库首次启动、离线启动、链接回退。
- 打包、签名说明、Release 附件、版本号。

**粗估：1 人 8～12 个工作日。** 其中翻译本身不是最大成本，core 错误、数据层中文和双语链接兼容才是主要工作量。

## 8. 测试与验收矩阵

| 项目 | 中文 | 英文 |

| 侧栏/卡片/详情/设置 | 全部中文 | 全部英文 |

| 非 MakerWorld 链接 | 不转换 | 不转换 |

### 自动化检查

1. `npm run i18n:check`：中英 key 一一对应，英文包不含未登记中文。
2. 硬编码扫描：渲染层 JS/HTML 中新增中文必须走字典（白名单：品牌名、模型名、注释）。
3. URL 单元测试：语言 × 站点 × 域名 × 语言段。
4. UI 探针：切换语言后各视图可见文本、布局、tooltip。
5. 全量 `npm run selftest`。
6. 打包后启动一次，确认安装版/绿色版都读取同一语言设置。

## 9. 风险与取舍

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 中文字符串量巨大 | 一次改完容易漏 | 先扫描清单，按 P0/P1/P2 分批；加硬编码检查 |
| core 错误是中文 `Error` | 英文界面弹中文 | 错误码 + 历史兼容翻译，重点路径优先 |
| 两站 ID 不通用 | 英文强制国际站可能 404 | 存双区域 URL；缺国际站就回退中国站并提示 |
| 英文更长 | 按钮/卡片溢出 | 英文专用布局走查；允许换行/缩短文案 |
| 默认分类/关键词是数据 | 英文首启分类仍是中文 | 首次启动按语言生成默认数据；老库不动 |
| README 默认语言改变 | 中文用户不习惯 | 先保留中文默认 + 英文链接；是否翻转单独确认 |
| 翻译质量不一致 | 术语混乱 | 先定术语表，再批量翻译；UI 走查统一口径 |

## 10. 需要你确认的决策

1. **GitHub 默认首页**：保持中文 `README.md` + 英文 `README.en.md`，还是改成英文默认、中文移到 `README.zh-CN.md`？
2. **英文版中国站专属模型**：国际站没有对应页时，是回退中国站并提示，还是坚持只开国际站（可能 404）？
3. **版本号**：按 `v1.2.0` 发布，还是先出 `v1.1.9-beta.1` 给朋友试用？
4. **默认分类/自动分类关键词**：英文首启是否生成英文默认分类和英文关键词别名？（建议是）
5. **内置耗材品牌名**：品牌名保留中文（遇果/R3D/大简），还是补英文显示名？（建议保留品牌原名，类型和说明英文化）
