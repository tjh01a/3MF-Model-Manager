## 0. 结论速览

| 方向 | 初步建议 | 一句话理由 |
| --- | --- | --- |
| 图标 | **Lucide（ISC）为主，Tabler Icons（MIT）为备选**；以「vendored SVG 路径」方式并入现有 `#i-*` sprite，**不引入运行时 npm 依赖** | `lucide-static` 官方直接提供 SVG sprite / 独立 SVG / SVG 字符串，专为无框架静态站点设计，与本项目「无打包器 + 严格 CSP + 离线」完全契合 |
| 动效 | **原生 CSS + View Transitions API + WAAPI 为主，零新依赖**；需要编排时才考虑 **Motion `animate()` mini（MIT，~2.6–3.1 kB gz）** | Electron 33.4.11 自带 Chromium **130.0.6723.191**，已支持 same-document（111+）与 cross-document（126+）View Transitions，无需升级、无需引库 |
| 不建议 | Animate.css（**Hippocratic License，非 MIT**）、Hover.css（商用授权有争议）、GSAP（非 MIT 的 Standard License）、Lottie（体积大且无设计交付链）、AutoAnimate（与本项目整块 DOM 替换冲突） | 许可合规与运行时冲突，详见 §3 §6 |

**核心判断**：本项目已经有 54 个手绘描边图标、23 个 `@keyframes`、40+ 条 `transition`、一套完整 z-index 与刷新调度。
「更美观、更简洁」的瓶颈**不是缺库，而是缺一致性**。因此建议走「统一图标笔触 + 收敛动效令牌 + 渐进增强的原生转场」，
而不是引入一整套组件库或重量级动画引擎。

### 3.1 View Transitions 关键事实（决定能不能用）

- 支持矩阵：Chromium **111+** same-document、**126+** cross-document、`view-transition-class` **125+**、types **125+**；Safari 18+ / Firefox 144+ 逐步跟进。本项目 Electron 33.4.11 = **Chromium 130**，全部够用。
- **渐进增强**：`document.startViewTransition` 不存在时，回退为「直接执行 DOM 更新」，不会报错、不会破坏布局。
- **必须自己做**的三件事：
  1. `prefers-reduced-motion` 下显式关闭 `::view-transition-*` 动画（浏览器不会自动关）；
  2. 每次调用前做特性检测，并统一封装成一个 helper（避免每个调用点各写一遍）；
  3. `view-transition-name` 在任一时刻必须唯一，列表里重名会**静默跳过整段转场**。
- 转场期间伪元素覆盖在页面之上并**拦截点击**，所以时长要压在 200–300ms；回调里不要做 IPC / 磁盘读取（渲染会被冻结）。
- 与本项目最大的冲突点：`renderSpecialView()` / `renderGrid()` 会替换 `#content`，若把 `#content` 整块纳入转场，几百张卡片的快照会明显掉帧；**只允许给「标题栏、详情抽屉、设置面板、单个命名元素」做转场**。

## 5. 初步选型建议

### 5.1 图标：Lucide（vendored SVG 路径）

1. 锁定一个 `lucide-static` 版本，只取项目实际用到的 ~60 个图标路径，生成到现有 sprite 中；
2. **保留 `#i-*` 命名空间与全部 54 个 id**（含重复别名），保证 `icon()`、`menu.js`、用户库里的 `cat.icon` 全部不变；
3. 补齐缺失的 `i-wrench` / `i-gear`，顺手统一 `stroke-width`（现有 1.8 可对齐 Lucide 的 2，或把 Lucide 路径统一按 1.8 渲染）；
4. 归档 LICENSE（ISC）与 Feather 衍生说明（MIT）到 `docs/licenses/`；
5. 生成脚本放 `tools/`（**仅构建期使用，不进运行时**），并在文档记录「怎么加一个新图标」。

### 5.2 动效：原生三件套 + 可选 Motion mini

| 层次 | 手段 | 依赖 |
| --- | --- | --- |
| 基础反馈（hover / 状态 / 展开收起） | CSS `transition` / `@keyframes`，统一 `--t*` 与 `--ease` | 0 |
| 视图 / 页面切换 | `document.startViewTransition()` 统一 helper + `::view-transition-*` CSS | 0 |
| 一次性编排（成功/失败、飞入、计数） | WAAPI `element.animate()`，全部可 `cancel()` | 0 |
| 弹性 / 时间轴（**仅当 M3 证明确有需要**） | Motion `animate()` mini，vendored 单个 ESM 文件 | MIT，~3 kB gz |

### 5.3 明确「不引入」的东西

任何需要打包器、需要框架、需要 CDN、需要 `eval`、需要远程字体的方案；任何自带 `*{transition}` 或注入全局 `<style>` 的库；
任何会观察 `#content` 子元素增删的自动动画库；任何非 ISC/MIT/CC0 且未做法务确认的许可。

| Q5 | **动效强度基线**：克制（≤200ms、仅 opacity/transform）/ 中等（含位移与共享元素转场）/ 明显（含列表 stagger、弹性）？ | 决定 M3 范围与性能预算 | 克制档；所有动效 ≤220ms，只动 `transform/opacity` |
| Q6 | **目标硬件与性能预算**：现 `probe-perf` 全量 ~68ms / patch ~1ms / 启动 460ms，动画后允许的上限？ | 几百张卡片同时动画是最主要的性能风险 | full ≤100ms、patch ≤5ms、启动动画结束 ≤600ms、无掉帧可感知卡顿 |
| Q7 | **无障碍要求**：是否必须严格 reduced-motion（含现有 `dropfx.js` 例外）？是否需要补 `:focus-visible`、高对比度？ | 项目已有全局压制但存在一处例外 | 全部动效遵守 reduced-motion，并补齐 `:focus-visible` |
| Q8 | **验收方式**：接受「截图 + 新增 CSS 探针」即可，还是要像素级视觉回归 / 人工视觉评审轮次？ | 当前**没有**视觉 diff 框架，引入需要新工具链 | 截图 + `tools/probe-motion.js` 样式/时序探针 + 人工看一次截图 |
| Q9 | **改造边界**：设备面板（`devices.css`）、模型优化面板（`meshopt.css` 655 行）是否纳入？ | 两套 CSS 相对独立，纳入会显著扩大回归面 | 本次只做主库界面（标题栏/侧栏/工具栏/卡片/统计条/详情/设置），两个面板只做图标映射 |
| Q10 | **第三方许可归档位置与 NOTICE 要求** | 再分发 ISC/MIT 资源需保留版权声明 | `docs/licenses/` + `README.md` 加一段致谢 |
| Q11 | **交付节奏**：按里程碑分次交付（每次截图）+ 中途可叫停，还是一次性完成？ | 影响回退开关与分支策略 | 按里程碑交付，每个里程碑结束跑一次全量回归并出截图 |
| Q12 | **是否需要「一键回到现状」开关** | 视觉改造主观性强，用户可能想 A/B 对比 | 提供 `ui.motionLevel=off` 与 `ui.iconSet=legacy` 两个设置项作为总回退 |
