# 03 · 接口契约（并行开发唯一依据 · 冻结版 v1.0）

> 所有子代理**必须严格按本文件实现导出**。文件所有权见 `02-可执行计划书.md` 第 5 节。
> 约定：core 层 CommonJS（`module.exports`），禁止 `require('electron')`；渲染层 ES Modules，禁止直接 `require` 任何 Node 模块，只能调用 `window.shelf.*`。
> 所有异步写操作返回 Promise；错误统一抛出 `Error` 且 `message` 为可读中文。
>
> **计数口径**：§12–§16 中「总 N 方法 / M 事件」是各追加契约当时的**历史基线**，不要按它们判断当前规模；
> 当前以 `electron/preload.js` 的 `METHODS` / `EVENTS` 为准，即 **127 方法 / 20 事件**
> （可用 `node tools/check-ipc-contract.js` 校验三方注册一致）。

### A-1 `src/core/model3mf.js`
```js
/**
 * 解析单个 3mf（只读，不写文件）
 * @returns {Promise<{ok:Boolean, error?:String, thumbnail:{entry,data:Buffer,mime}|null, meta:Object}>}
 * meta 字段见 1.2；失败时 ok:false + error，绝不抛异常到扫描循环外
 */
async function parse3mf(filePath, options = {})   // options: { withThumbnail:true, withMeta:true, maxModelBytes: 24*1024*1024 }
function pickThumbnailEntry(entries, relsXml)      // 纯函数，返回条目名或 null；供单测
function parseRels(xml)                            // -> [{target,type,id}]
async function readThumbnail(filePath)             // -> Buffer|null（便捷封装）
module.exports = { parse3mf, pickThumbnailEntry, parseRels, readThumbnail }
```
缩略图回退顺序（**必须实现**）：
1. `_rels/.rels` 中 `Type` 含 `/metadata/thumbnail` 的 `Target`
2. `_rels/.rels` 中 `Type` 含 `cover-thumbnail-middle` / `cover-thumbnail` 的 `Target`（拓竹）
3. 固定候选：`Thumbnails/thumbnail.png|jpg|jpeg`、`Metadata/plate_1.png`、`Metadata/plate_1_small.png`、`Metadata/top_1.png`、`Metadata/plate_no_light_1.png`
4. 包内所有 `.png/.jpg/.jpeg` 中**解压后体积最大**者（排除 `pick_*` 等小于 1KB 的贴图）
所有匹配大小写不敏感；`Target` 可能带前导 `/`，需归一化；需做 zip-slip 防护（拒绝 `..`）。
meta：`3D/3dmodel.model` 用正则统计 `<object`/`<item`/`<build` 数量（大文件按 maxModelBytes 截断，不解析完整）；`Metadata/project_settings.config` 是 JSON，取 `layer_height`/`sparse_infill_density`/`printer_model`/`filament_type` 等；`slice_info.config` 取 `X-BBL-Client-Version`；`model_settings.config` 取对象名列表计入 `meta`；`filament_sequence.json` 长度计入 filamentCount；`hasMultiColor` 由实际颜色数 / 槽位数 / `filament_sequence` 长度 >1 判断。

耗材颜色（2026-11-14 增补）：`project_settings.config` 的 `filament_colour`（回退 `filament_multi_colour` / `default_filament_colour`）是 **AMS 槽位配置色**，数组下标必须原样保留（空/非法值留 null，否则与 `filament_type` 错位）；`model_settings.config` 里每个 `<metadata key="extruder" value="N"/>` 才是零件真正使用的槽位（1-based，`0` 表示跟随默认，按槽 1 处理）。优先按使用槽位取色并去重，标 `colorSource='objects'`；没有槽位信息才退回全部配置色，标 `'project'`；无色值标 `'none'`。色值统一由 `normalizeColor()` 收敛为 `#RRGGBB`，最多 16 个。旧库记录由 `src/core/colors.js` 的 `backfillFilamentColors()` 轻量重解析补齐，只合并这三个字段与 `hasMultiColor`，不整体替换 `meta`。任一条目解析失败都只降级，不影响整体。

### A-2 `src/core/scanner.js`
```js
class Scanner extends EventEmitter {
  constructor({ store, thumbs, options = {} })
  // options: { concurrency=4, excludeDirs=[], maxDepth=12, hashEnabled=true, parseMeta=true }
  async scanAll({ folderIds, force = false } = {}) : Promise<ScanReport>
  async scanFolder(folder) : Promise<ScanReport>     // Folder 对象
  async scanPath(dirPath) : Promise<ScanReport>      // 便于测试直接扫一个路径
  cancel() : void
  getStatus() : { running, phase, current, total, message, startedAt }
}
// ScanReport = { added, updated, unchanged, missing, failed, duration,
//                files:[{path,action,error?}], duplicateGroups:Number }
// events: 'progress' {phase,current,total,message,percent}, 'done' report, 'error' Error
```
行为要求：
- 递归 `fs.promises.readdir({withFileTypes:true})`，不跟随符号链接；忽略 `IGNORE_DIRS` + `excludeDirs`；超过 `maxDepth` 停止深入。
- 收集 `.3mf`（大小写不敏感），跳过 0 字节与 >500MB 文件（计入 failed 并给中文原因）。
- **增量**：已有记录且 `size` 与 `mtime` 均未变 → `unchanged`，跳过解析与哈希。
- 新增/变更：并发限流调用 `parse3mf`，缩略图交给 `thumbs.ensureFor(record)`（传入 `{parseResult}` 可复用解析结果，避免重复解压）；`hashEnabled` 时算 `hashFile`。
- 磁盘上已存在但库中缺失标记 `missing`；扫描结束后调用 `duplicates.annotate()` 写回重复分组。
- 每个文件处理完 emit `progress`（内部节流 ≤ 20 次/秒），支持 `cancel()` 提前停止。
- 单个文件失败不得中断整体，记录到 `files` 且 `failed++`。
- **扫描结果写入 store 必须走 `store.updateLibrary()`**，不得自行写文件。

```js
     //   → { ok:true, exePath:'…\\snapmaker-orca.exe', fixed:true }
     //   找不到才 { ok:false, reason:'这是文件夹，里面没找到 .exe：…' }
  async open(ids, { slicerId=null, slicer=null } = {}) : Promise<{launched:String[], failed:Array<{id,error}>}>
     // slicerId 走设置查找；slicer 直接吃一个对象 —— detect() 每次返回的 id 都是新造的随机值，
     // 拿它回设置里查必然查不到，所以「探测到但没写进设置」的项必须走 slicer 这个口子。
     // 取默认或指定 slicer；对每个 id 找 record.path，检查文件存在；
     // child_process.spawn(exePath, [...argsArray, filePath], {detached:true, stdio:'ignore', shell:false}).unref()
     // 成功后调用方负责 markOpened（本模块只 emit 'opened' 事件，事件带 ids）
  async reveal(recordOrPath) : Promise<void>   // explorer /select, 或 shell.showItemInFolder 的等价命令（win: explorer.exe /select,"path"）
  async openDataDir() : Promise<void>
  async trash(paths) : Promise<{ok:String[], failed:Array<{path,error}>}>  // 优先用 PowerShell Shell.Application 回收站；不可用则抛可读错误，绝不 fs.unlink
  async testLaunch(exePath) : Promise<{ok:Boolean,error?:String}>          // 可选：不实际启动 GUI，仅校验可访问
}
```
`args` 是字符串，按空格拆分（支持简单引号）；**禁止 shell:true**。Windows 路径含空格必须作为单个数组元素传递。

## 6. 错误与反馈规范

- 所有 core 抛出的 `Error.message` 必须是**可读中文**（例："文件不存在：D:\\...\\a.3mf"）。
- IPC handler 统一 try/catch，失败返回 `{__error: message}`？**不**——统一 `throw`，preload 层把 rejection 交给 UI 的 `api.js` 统一 toast；致命错误额外 emit `app:error`。
- 危险操作（磁盘重命名冲突、移入回收站、删除分类/标签、恢复备份、导入覆盖）必须 UI 二次确认并列出受影响的完整路径/名称。
- 成功反馈用 Toast（2.5s 自动消失），批量操作 Toast 带"撤销"。

## 10. 追加契约 · 界面图标与动效（2026-11-15）

以下四项为冻结契约，渲染层与构建期工具按此实现。

### 10.1 `settings.ui` 两个新字段

| 字段 | 取值 | 默认 | 语义 |
| --- | --- | --- | --- |
| `iconSet` | `lucide` / `legacy` | `lucide` | 切换两套 sprite 的 `<symbol>` 内容；`legacy` = 改造前自绘图标 |
| `motionLevel` | `full` / `reduced` / `off` | `full` | 新增动效档位；`off` 时所有新增动效短路 |
| `motionFollowSystem` | `true` / `false` | `false` | **2026-11-19 新增**：是否让系统「减少动态效果」压制应用内档位。默认 false = 应用设置优先 |

写入链路（**无字段白名单**）：

```
设置页 views/settings.js applyUI() → api.settingsUpdate({ ui: { iconSet, motionLevel } })
  → store.updateSettings(patch) → mergeSettings 深合并
  → mergeSettings 对 ui.* 没有字段白名单，任意 ui.* 键都会被合并并原子落盘
  → app.js bootstrap 读取 settings.ui → applyIconSet() / applyMotionPrefs()
  → 写 html 的三个 data 属性：`data-iconset`（图标集偏好）/ `data-motion`（用户动效档位）/ `data-motion-effective`（降级后实际档位）
```

- 默认值由 `src/core/constants.js` 的 `DEFAULT_SETTINGS.ui` 提供；旧 `settings.json` 缺字段时由
  `mergeSettings` 补齐，**不需要数据迁移**，也不新增 IPC（沿用既有 `ui` 写入链路）。
- **`legacy + off` 等价于改造前界面**（两个总回退开关，见 `docs/09` A.10.3）。
- **动效优先级（2026-11-19 修订）**：应用内档位 > 系统偏好。`ui.motionFollowSystem` 为 `false`（默认）时，
  即使系统开了「减少动态效果」，也按 `motionLevel` 播放——与多数桌面软件/游戏一致；
  只有用户显式打开「跟随系统」且系统命中 reduce 时，才降为 `reduced`。`off` 永远一票否决。
- 降级后的实际档位写 `html[data-motion-effective]`，**不回写**用户存的 `motionLevel` / `motionFollowSystem`。
- `base.css` 的全局限动规则（把 `animation-duration` / `transition-duration` 压到 `.001ms`）也按
  `html:not([data-motion-effective="full"])` 生效，否则 JS 档位改了、CSS 仍被系统媒体查询压住（本轮踩到的坑）。

## 11. 追加契约 · 预设词库自动分类（2026-11-15）

依据 `12-预设词库自动分类-调研与计划书.md`（已实施）与 `docs/09-实现说明书.md` 附录 **A.11**。
新增文件 `src/core/classify.js`、`tests/classify-tests.js`；IPC handler 从 98 个增加到 **101** 个；
**无新增运行时依赖**，`library.json` 的 `schemaVersion` 不变，分类结果只写 `categoryId` 与 `autoClassified`。

### 11.1 `settings.classify`（新顶层组）

```js
settings.classify = {
  enabled: true,          // 总开关：false 时扫描与启动都不跑；手动 classifyRun 可 force
  onScan: true,           // 扫描新导入 / 变更文件时即时匹配
  onStartup: true,        // 每次启动补一次未分类
  rules: [                // 空数组 = 尚未生成，运行时回落到内置预设
    { id: 'rule_test', categoryId: 'cat_xxx', keywords: ['测试', '校准'] },
  ],
  lastRunAt: 0,           // 上次「真的分到东西」的时间（ms）
  lastRunStat: null,      // { scanned, assigned, skipped } | null
}
```

| 字段 | 默认值 | 语义 |
| --- | --- | --- |
| `enabled` | `true` | 总开关；关闭后扫描与启动都不自动分类 |
| `onScan` | `true` | 扫描时对空 `categoryId` 的记录即时匹配 |
| `onStartup` | `true` | 启动后 1.6s 补跑一次未分类 |
| `rules` | `[]` | 每条规则 `{ id, categoryId, keywords[] }`；数组顺序即优先级 |
| `lastRunAt` | `0` | 只在 `assigned > 0` 时更新 |
| `lastRunStat` | `null` | 只存 `scanned / assigned / skipped`，不含 `pending` |

**写入与合并规则**（`src/core/store.js` 的 `mergeSettings`）：

- 顶层键浅合并；`classify` 是对象，按 `Object.assign({}, base.classify, patch.classify)` 合并，所以
  `settingsUpdate({ classify: { rules: [...] } })` **只替换 `rules`**，`enabled / onScan / onStartup / lastRunAt / lastRunStat` 全部保留。
- **`rules` 是数组，按整体替换处理**（`mergeSettings` 对数组直接赋值，不做逐项合并）。改一条规则也必须读出整份数组、改完再整份写回；不能只发 `[{ id, keywords }]`，否则其余规则会丢。
- 默认值来自 `src/core/constants.js` 的 `DEFAULT_SETTINGS.classify`；旧 `settings.json` 缺该组时由 `mergeSettings` 自动补齐，**不需要数据迁移**。
- 运行时若 `rules` 为空，`classify.resolveRules()` 会回落到 `presetRules(当前分类)`；设置页首次打开「自动分类」tab 时会把预设写进 `rules`，之后以用户编辑为准。

### 11.2 IPC（3 个，channel `shelf:<name>`）

### 11.4 `ModelRecord.autoClassified?: Boolean`

- 可选字段。`true` = 该 `categoryId` 由预设词库自动写入；`false` = 自动结果已被撤销；缺省 = 人工分类或从未分类。
- 只有 `src/core/classify.js` 会写它：`applyToRecord()` 命中时置 `true`，`undoAutoClassified()` 与「命中已删除分类」时置 `false`。

- 自动分类永远只处理 `categoryId` 为空的记录；已有分类（含人工分类）不会被覆盖，也不会被补上 `autoClassified`。

### 11.6 `ui.makerWorldCn: Boolean`

- 默认 `true`。`openExternal` 把 `makerworld.com` 的链接换成 `makerworld.com.cn`（路径 / query / 锚点保留），
  并把 `/en/`、`/es/`、`/zh-cn/` 等语言段统一成 `/zh/`；`false` 时原样打开国际站。
- 背景：中国站与国际站是**独立模型库，ID 不通用**（实测国际站 `models/3377037` 在中国站不存在），
  国服没同步的模型会显示「模型不存在」，此时用户可手动关掉开关。
- 老版本默认 `false`；升级时通过 `ui.makerWorldCnMigrated` 只迁移一次，用户手动关闭后不再翻回。
- 只影响 `openExternal`，不修改 `ModelRecord.sourceUrl` 的存储值；非 makerworld 域名不受影响。

### 11.7 摄像头 IPC（`cameraFrame` / `cameraDetect`）

| 方法 | 参数 | 返回 | 说明 |
| --- | --- | --- | --- |
| `cameraFrame` | `id`（设备 id） | `{ ok: true, base64 }` | 单帧 JPEG（base64，不含 `data:` 前缀）。约 3~6 秒 |
| `cameraDetect` | `id` | `{ ok: true, shots: [base64, base64] }` | 连一次抓两帧，间隔 3 秒；约 10~14 秒 |

- 仅 `kind === 'bambu'` 的设备可用；其它设备抛「这台设备暂不支持机内摄像头」。

| 设置字段 | 默认 | 作用 |

**IPC 方法**

| 方法 | 参数 | 返回 |
| --- | --- | --- |
| `monitorHistory` | `printerId?, limit?` | `Session[]`（按开始时间倒序，`printerId` 为空 = 全部设备） |
| `monitorChart` | `printerId?, sessionId?` | `{ sessions: SessionMeta[], session: Session\|null, model: ChartModel }` |
| `monitorLatest` | `printerId?` | 最近一条 `Session \| null` |
| `monitorStatus` | — | `{ running, file, sessions, points, active[], loadError, intervalSec }` |
| `monitorClear` | `printerId?` | `{ cleared }`；不传 id = 清空全部 |
| `notifyTest` | — | 立即发一条测试通知，payload 与真实通知同构 |

- `Session`：`{ id, printerId, printerName, jobName, startedAt, updatedAt, endedAt, points[] }`。
- `points[i] = [t, percent, nozzleCur, nozzleTarget, bedCur, bedTarget]`（紧凑数组，最多 1800 点，超出丢最旧的）。
- `ChartModel` 由 `src/core/monitor.js` 的 `buildChartModel()` 纯函数生成：双轴（左温度 ℃ / 右进度 %）、四条 series（喷嘴 / 喷嘴目标虚线 / 热床 / 进度）、网格、时间刻度与统计。坐标计算全在主进程，渲染层只套 SVG 外壳。
- 落盘：`data/monitor/history.json`，`tmp + rename` 原子写；每 12 个点或 30 秒、任务结束、退出前各 flush 一次。异常退出后重新打开会把「进行中」的 session 自动收尾。

**事件 `printers:notify`**

| 字段 | 说明 |
| --- | --- |
| `printerId` / `printerName` / `jobName` | 哪台机器、哪个任务 |
| `kind` | `finished` / `error` / `paused` / `test` |
| `title` / `body` | 系统通知与应用内 toast 共用的文案 |
| `at` | 时间戳 |
| `system` | 是否弹系统通知（= `notify.system`） |

去重规则：同一个任务的同一种提醒**只发一次**；不同类型之间不互相冷却（打完立刻报错也要各提醒一次）；同类型不同任务 60 秒内不重复。`online:false` / `connecting` 中间态既不通知也不覆盖上一次在线状态，避免 MQTT 重连重复弹「已完成」。刚刚启动、第一次见到某台设备时不补发历史通知。

| `cameraFrame(id)` | `{ ok: true, base64, staleSec, source, static, notice }`，`source` ∈ `bambu` / `u1-live` / `moonraker-webcam` / `moonraker-camera` / `url`；`u1-live` 是 G-code 驱动的真实时抓拍，`static` 表示来自打印机上的静态快照文件，`notice` 是抓拍失败原因 |
| `cameraDetect(id)` | `{ ok: true, shots: [base64, base64], staleSec, source, static }` |

- 不再对非拓竹机型抛「暂不支持机内摄像头」；取不到画面时抛可读中文错误，由渲染层显示在卡片上。
- `staleSec` 是**画面多久没真正刷新**（秒）。首次抓取以文件 `modified` 为准；内容变了以本次抓取为准（兼容 mtime 不更新的固件）；内容不变仍以 `modified` 为准。不能只看内容比较——否则一张停更数小时的旧图在首次抓取时会报 0 秒。
- `source==='u1-live'` 时卡片显示绿色「实时抓拍」，这不是常驻视频流，而是每 15 秒最多一次、由 `TIMELAPSE_TAKE_FRAME DEBUG=1` 驱动的当场拍照；节流窗口内复用上一帧并带真实年龄。
- `static=true` 时卡片显示「静态快照」与「画面停在 X」，并给出填自定义摄像头地址的提示；不得把静态文件当实时流呈现。
- 任意机型都可以配置 `printer.cameraUrl`（快照或 MJPEG），配置后优先于机型默认通道。

### 16.2 数据字段

```js
printer.cameraUrl   // string，可选；空串 = 用机型默认通道
status.temps.heads  // Array<{index, cur, target, active}> | null；单头机器为 null
status.temps.chamber // {cur, target} | null；来自 temperature_sensor cavity
```

`temps.nozzle` 语义不变（当前活跃头），供监控采样与旧界面兼容。

### 16.3 渲染层行为

- 设备卡温度区：`heads` 存在时渲染 T1–T4（`grid` 等宽），否则退回单个「喷嘴」；热床、腔体随后。
- 摄像头区块对所有机型渲染；有空画面时显示「点『摄像头』查看」，取帧失败显示原因 + 「可在编辑里填摄像头地址」。
- 「打印机检测」完成**自动弹出**对比窗；关闭（按钮 / Esc / 遮罩）都会 `stopCam(id)`，画面与轮询一起清掉。
- 关闭设备面板时清空所有帧缓存，下次打开不残留旧画面。
- 点「摄像头」立即进入 `.dev-cam.is-loading` 等待态；取帧成功或失败都要清理。「打印机检测」按钮同步 `.is-loading` 倒计时。

## 17 · 分阶段启动信号（2026-11-19）

主进程 → 渲染层新增事件 `boot:stage`（加入 preload `EVENTS` 白名单，IPC 契约事件数 20）：

```js
{ name: 'starting'|'dirs'|'store'|'data'|'services'|'ipc'|'backend', percent: 8|15|34|48|64|78|92 }
```

- `preload.js` 缓存**整段**历史，订阅时按序补发（阶段早于 ES Modules 加载是常态）。
- `api.js` 转成 `window` 的 `shelf:bootstage`；`boot.js` 排队展示，每阶段至少 200ms、总等待上限 900ms，收尾推到 100% 再淡出。
- 诊断字段 `window.__printshelfBoot.stage` / `.stages`；`__printshelfBootApi.setStage(name, percent)` 可手动驱动。
- `services.init({onStage})` 只是视觉回调，不参与任何 await；`startBackground()` 在首屏后启动 chokidar，幂等。
- 启动动画受 `data-motion-effective` 控制：只有用户开启「跟随系统」且系统 reduce 时才降档，否则系统开关不改变应用内动效。

## 18 · 设备操作按钮语义（2026-11-19）

按钮文案必须带操作对象，禁止裸写「暂停 / 停止 / 取消」：

- `data-act="dev-cmd" data-cmd="pause"` → **暂停打印**；确认框取消按钮 = 「不暂停，返回」。
- `data-cmd="resume"` → **继续打印**。
- `data-cmd="stop"` → **取消打印**；两道确认（说明框 + 输入「取消打印」），确认框必须明写「不关闭摄像头预览、不移除设备」。
- `data-act="dev-cam"` → **查看摄像头 / 关闭预览**，title 写明「不影响打印任务」。
- `data-act="dev-remove"` → **移除设备**，确认框取消按钮 = 「不移除，返回」。

`confirmDialog()` 新增可选 `cancelText`（默认「取消」），用于把危险确认框的否定按钮写成人话。
