# 02 · 可执行计划书（PrintShelf v1.0）

## 0. 交付目标

一个双击即可运行的本地 Windows 桌面应用：`npm start` 或 `启动.bat` 打开窗口；所有索引、分类、标签、备注、缩略图缓存、配置保存在项目 `data/` 目录；不联网、不上传、不改动用户模型文件（除非用户明确执行重命名/回收站操作）。

**技术栈**：Electron 33（主进程）+ Node 22 纯 CommonJS 核心层 + 原生 ES Modules/CSS 渲染层；本地 JSON 持久化 + PNG 缩略图缓存；`adm-zip` 解析 3MF、`chokidar` 目录监视。无构建步骤、无原生模块、无云端依赖。

## 2. 交互流程

### 2.1 首次启动（空状态 → 有内容）
```
启动 → 空状态引导页（插画 + "添加第一个模型文件夹" + "扫描示例目录"）
     → 拖拽文件夹 或 点击选择目录（系统对话框）
     → 自动开始扫描（顶部进度条 + 实时"已发现 N 个 3mf"）
     → 缩略图异步落盘，卡片逐张出现
     → 完成 Toast："新增 49 个模型，2 个重复，0 个失效"
```
全程 **2 步**（选目录 → 自动完成）。

### 2.2 日常找模型 → 打印（核心路径）
```
打开应用 → 网格默认按"最近添加"排序
 → 侧栏点智能视图（如"未打印"）或直接在搜索框输关键字（即时过滤，无需回车）
 → 悬停卡片看快捷操作，空格大图预览，← → 翻看
 → 选中 → 卡片上点状态徽标直接改状态 / 右侧详情写备注、加标签、评分
 → 点"用切片软件打开"（或 Ctrl+O / 双击主按钮）
 → 切片软件启动并载入 3mf；应用记录 lastOpenedAt、openCount，模型出现在"最近打开"
```
核心路径 **≤ 3 次点击**。

### 2.3 批量整理
```
Ctrl+A / 框选 / Shift 连选 → 底部浮出批量条
 → 一次设置分类 / 加标签 / 设打印状态 / 收藏 / 移出索引
 → Toast 提供"撤销"（Undo 栈保存操作前快照）
```

### 2.4 重复与失效处理
```
侧栏"重复文件" → 按组并排展示缩略图、路径、大小
 → 用户手动选择保留项，"移出索引"或"移入回收站"（二次确认 + 列出路径）
侧栏"失效文件" → 自动在监控目录按文件名+大小找候选 → 一键"重新定位"
 → 或手动选新路径；人工元数据全部保留
```

### 2.5 切片软件配置
```
设置页 → 自动探测本机已安装切片软件（Bambu Studio / OrcaSlicer / PrusaSlicer / Cura / Creality Print）
 → 列表勾选启用、设默认、可手动添加 exe 路径（校验 + 试启动）
 → 保存后，工具栏"打开方式"下拉可临时切换软件
```

## 3. 数据范围

### 3.1 只读取什么
- 用户显式添加的监控目录内、扩展名为 `.3mf`（大小写不敏感）的文件；
- 每个 3mf 包内的：`_rels/.rels`、`[Content_Types].xml`、`Thumbnails/*`、`Metadata/*.png|jpg`、`3D/3dmodel.model`、`Metadata/project_settings.config`、`Metadata/model_settings.config`、`Metadata/slice_info.config`、`Metadata/filament_sequence.json`；
- 本机常见安装路径下的切片软件 exe（仅做存在性检查）。

### 3.2 只写入什么
- 项目 `data/` 目录内：`library.json`、`settings.json`、`thumbs/*.png`、`backups/*.json`；
- 用户主动执行时：模型文件重命名、移入系统回收站（需二次确认）。

### 3.3 绝不写入
- 用户监控目录内的任何 3mf 内容（不改写工程文件）；
- 任何网络请求、遥测、云端存储；
- 监控目录以外的用户文件。

### 3.4 数据文件结构
```
data/
├── library.json        索引主库（models / categories / tags / savedViews / scanMeta）
├── settings.json       监控目录、切片软件、UI 偏好、扫描规则
├── thumbs/<sha1>.png   从 3mf 抽取并缓存的缩略图
├── backups/            写入前自动轮转备份（默认保留 10 份）
└── logs/app.log        可选运行日志（本地）
```
完整字段定义见 `docs/03-接口契约.md`。

| A5 | 新建分类/标签、批量归类、批量改状态、收藏、评分、备注持久化 | 重启应用后数据仍在 |

| A7 | 内容哈希分组正确识别重复；文件移走后标记失效；重新定位恢复 | 造重复文件与临时移走验证 |
| A8 | 自动探测出本机 Bambu Studio / Creality Print；一键调用 spawn 成功 | 试启动返回 launched（可用假 exe 验证参数传递） |
| A9 | 网格/列表切换、深浅主题、空状态、Toast、错误提示均正常 | 截图走查 |
| A10 | 索引导出/导入、自动备份、损坏恢复 | 单元测试 |

### B. 非功能验收
- 冷启动 < 3 s；1000 条索引下搜索响应 < 100 ms（前端本地过滤 + 后端查询）。
- 扫描 1000 个文件不阻塞 UI（主进程异步 + 进度事件节流）。
- 任何异常都以可读中文提示呈现，不出现未捕获错误弹窗。
- 全部数据文件可直接用文本编辑器打开查看，无二进制黑盒（缩略图除外）。
- **离线可运行**：断网后所有功能正常。

### C. 验证手段（不依赖人工点界面也能跑）
1. `npm test` —— core 层单元测试（Node 直跑）。
2. `npm run smoke` —— 指向真实工作区 49 个 3mf 的端到端流程：扫描→解析→缩略图→去重→检索→批量→重命名→失效→重新定位→导出导入→设置。
3. `electron . --smoke` —— 无头自检：窗口创建、协议注册、全部 IPC handler 注册，输出 JSON 结果后自动退出。
4. `electron . --capture=<png>` —— 自动截图 UI，供视觉走查。

## 7. 关键设计决策（已定，不再变更）

- **路径为唯一键**：规范化小写绝对路径；文件移动 = 失效 + 重新定位，元数据不丢。
- **增量扫描**：`size + mtime` 未变则跳过解析，避免每次全量重解 3mf。
- **缩略图协议**：`shelf://thumbs/<fileName>`，主进程注册自定义协议映射到 `data/thumbs/`，UI 用 `<img src>` 直接加载。
- **哈希策略**：SHA-1 内容哈希仅对新增/变更文件计算，用于重复分组；大文件（>200 MB）跳过精细解析但保留基本索引。
- **删除策略**：默认只移出索引；移入回收站需二次确认并列出完整路径；索引写入前自动备份。
- **状态机**：`unprinted → queued → printing → printed`，任意状态可手动切到 `failed` 或重置。
- **UI 状态**：前端只持有一份 `state`（query / selection / view / settings），所有持久化交给主进程，避免双写不一致。
