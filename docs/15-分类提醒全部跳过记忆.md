# 15 · 分类提醒「全部跳过」记忆 —— 说明

> 时间：2026-11-18
> 触发：用户反馈「这些点了全部跳过，下次打开软件则不应该会跳出来这个窗口显示这些模型没有归类」

---

## 1. 问题根因

「没匹配上分类」弹窗的「全部跳过」按钮原本只做 `close(null)`——只是关闭弹窗，**不记任何状态**。而 `classifyRun()` 每次启动都从全部未分类模型重新计算 `unmatched`，所以同一批模型每次开机都会再弹一次。

用户库里实测：**41 个**未分类模型全部匹配不上任何词库，而弹窗只展示前 **20** 条。这意味着即使只记弹窗展示的那 20 条，下次仍会弹出剩下 21 条里新的 20 条——用户体验上等于「点了全部跳过没用」。

## 2. 方案

**记忆「跳过决定」到设置，而不是关掉整个提醒开关**——这样是"这几张不再提醒"，以后出现新的未匹配模型仍会提示。

1. 设置新增 `classify.skippedIds: string[]`（默认空、上限 500，防 settings.json 膨胀）。
2. 点「全部跳过」→ 写 IPC `classifySkipUnmatched(ids)`。核心用 `collectUnmatchedIds()` 重新算出**当前全部**未匹配模型 id（不只是弹窗展示的 20 条）合并写入。
3. `classifyUncategorized()` 生成 `unmatched` 时用 `Set(skippedIds)` 过滤——下次启动这批不再进弹窗。
4. 只影响**提示列表**，不影响分类逻辑：用户之后在设置里加了关键词，`onStartup` 分类仍能把它们分好。
5. 设置页「自动分类」加「恢复提醒」按钮（有跳过记录时显示），可清空名单，避免用户误点后永久看不到提醒。

## 3. 语义边界（重要）

| 用户操作 | 是否记跳过 | 理由 |
|---|---|---|
| 点「全部跳过」 | ✅ 记录全部未匹配 | 明确的"这些我都不想分类"决定 |
| 点「应用」且选了分类 | ❌ | 选中的归类了；没选的保持原样，下次仍提示 |
| Esc / 点 X / 点遮罩关掉 | ❌ | 随手关掉不等于跳过决定 |

弹窗返回值因此从「数组或 null」改为 `{picked, skipped}` 对象（或 null），见 `docs/03 §14.4`。

## 4. 验证

- 单测 `tests/classify-tests.js`：**64 条 / 0 失败**，新增 11 条覆盖 collectUnmatchedIds、过滤、去重、上限、清空后恢复、configOf 容错。
- UI 探针 `tools/probe-classify-skip.js`：实测 `unmatchedBefore=20` → 点全部跳过 → `skippedAfter=41`（全部，不只 20）→ `unmatchedAfter=0`（下次不再弹）→ 设置还原 → Esc 不记跳过，**5 项全 true**。
- 全量：语法 106 文件 / 0 错误；契约 **123 方法 / 19 事件一致**；8 套 selftest 全 0 失败；Electron smoke `ok:true`。

## 5. 恢复提醒（反悔路径）

设置 → 自动分类，当 `skippedIds` 非空时会显示一行提示「已跳过 N 个模型的分类提醒」和「恢复提醒」按钮。点了会弹二次确认（避免误触），确认后把名单清空，这批模型下次启动重新参与提醒。

配套修复：`openSettings()` 原来只读 `state.settings` 内存快照。如果名单是被别处改的（另一窗口 / 直接走 IPC），面板会显示旧状态、按钮不出现。现在进入「自动分类」tab 会额外 `api.settings()` 拉一次最新快照再渲染。详见 `docs/09` 附录 A.17.4（陷阱 53）。

验证探针 `tools/probe-classify-skipreset.js`（截图走 `data/reg/`，不占文档位）：假名单 2 条 → 按钮出现且文案带数量 → 点按钮弹确认 → 确认后 `skippedIds` 清 0，`ok:true`。
