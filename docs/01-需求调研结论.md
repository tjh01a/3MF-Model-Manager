# 01 · 需求调研与常见功能范围梳理（结论）

调研时间：2026-11-12　｜　对象：本地 3MF 模型管理桌面应用（内部代号 **PrintShelf / 印架**）

---

## 一、事实依据（本机实测 + 规范/竞品调研）

### 1. 3MF 文件本身能提供什么

3MF 是 OPC/ZIP 容器，本身就是一个"自带元数据的模型包"。实测本机 3 个样本 + 规范资料结论：

| 可提取内容 | 位置 | 实测情况 |
|---|---|---|
| 缩略图 | `_rels/.rels` 中 `.../metadata/thumbnail` 关系指向的 Target；拓竹另有 `schemas.bambulab.com/.../cover-thumbnail-middle`、`-small` 关系 | 本机样本为 `Metadata/plate_1.png`（3.9 KB）、`plate_1_small.png`（1.8 KB）、`top_1.png`、`plate_no_light_1.png`、`pick_1.png`；标准切片器常见 `Thumbnails/thumbnail.png` |
| 几何与对象名 | `3D/3dmodel.model`（XML，`<object>` / `<item>` / `<build>`）、`3D/Objects/*.model` | 可统计对象数、零件名、单位 |
| 工程参数 | `Metadata/project_settings.config`（JSON，数百项）、`model_settings.config`（JSON） | 层高、填充、耗材、打印机型号等 |
| 切片信息 | `Metadata/slice_info.config`、`filament_sequence.json` | 切片器版本 `X-BBL-Client-Version`、耗材序列 |
| 核心属性 | `[Content_Types].xml`、Core Properties（可选） | 标题 / 设计师 / 版权 |

**关键结论 1：缩略图不要自己做 3D 渲染。** 3MF 内嵌 PNG 已足够，直接抽取并缓存即可；必须写"多来源回退链"——标准关系 → 拓竹关系 → 常见路径 → 包内最大 PNG，否则极简格式（本机 `测试A_极简格式.3mf` 完全没有图片）会开天窗，此时用优雅的占位图。

**关键结论 2：3MF 可顺手解析出对象数、打印设置摘要、切片器版本**。成本极低（读几个文本条目 + 正则统计），但让卡片信息从"一个文件名"变成"有内容的资产"，是性价比最高的加分项。

### 2. 同类工具的功能边界

调研对象：Printventory（开源本地管理）、Modelist（桌面图库）、MeshVault（Windows 库）。三者高度趋同的"标准功能集"是：

- 扫描本机目录、**不移动原文件**，只建索引（文件夹始终是事实来源）
- 缩略图网格 / 列表切换、即时搜索、多条件筛选、排序
- 标签、收藏/集合、备注、来源链接、设计师
- 打印生命周期：想打 → 排队 → 打印中 → 已打印 / 失败，含打印次数与上次打印时间
- **内容哈希去重**（并支持缩略图并排对比，只标记不自动删）
- 多切片软件配置 + 一键送切片软件
- 数据库与缩略图全部本地；备份/恢复；多视图；右键菜单；批量编辑

用户提出的需求与行业共识完全吻合，说明范围合理，不需要砍功能，重点是**把这些功能做成"少步骤"**：状态在卡片上直接点、批量操作浮出工具条、全局快捷键、拖拽即导入。

### 3. 本机环境事实

- Node 22.22.2 / npm 10.9.7 / Python 3.13 / Windows 11；Electron 33、adm-zip、chokidar 已实测可安装可用。

## 二、简要结论

1. **产品定位**：一个"只读索引层"桌面应用。**绝不移动、改写用户的模型文件**（唯一例外是用户主动要求的重命名/移入回收站，且必须二次确认）。文件夹结构始终是事实来源，索引只是加速层。这是所有同类工具的共同底线，也决定了失效文件、重复文件都只能"标记"而非"自动处理"。
2. **技术选型**：Electron 桌面应用 + 纯 Node 核心层 + 原生 ES Modules 渲染层。核心层不依赖 Electron，可在 Node 下直接跑自动化测试（这解决了"GUI 应用难验证"的问题）；数据用本地 JSON（原子写 + 自动备份）+ 独立 PNG 缩略图缓存，零数据库、零原生编译、零云端依赖。缩略图通过自定义 `shelf://` 协议直出文件，避免大 base64 传输。
3. **数据范围**：只索引 `.3mf`；不上传任何内容；不读取监控目录以外的文件；所有数据落在本机 `data/` 目录，用户可直接查看、复制、备份、迁移。
4. **功能范围**：以用户需求为必做基线（扫描 / 分类标签收藏 / 搜索筛选排序 / 批量归类重命名 / 缩略图缓存 / 网格列表 / 备注打印状态最近使用 / 重复与失效识别 / 切片软件联动），加上下面一组"简单但明显好用"的加分功能。

## 三、自主补充的加分功能（筛选原则：实现简单、使用频次高、不增加用户负担）

### 交互减步（最高优先级）
1. **拖拽导入**：把文件夹或 .3mf 直接拖进窗口 → 加监控目录 / 导入单个文件，不用点"选择文件夹"。
2. **全局快捷键**：`/` 聚焦搜索、`Ctrl+A` 全选、`F2` 重命名、`Ctrl+D` 收藏、`Ctrl+O` 送切片软件、`Space` 大图预览、`Delete` 移出库、`1~5` 评分、`Esc` 关闭。
3. **卡片内直接改状态**：点状态徽标即循环切换（未打印→待打印→打印中→已完成），不必打开详情面板。
4. **多选浮出批量条**：选中即出现"设分类 / 加标签 / 设状态 / 收藏 / 移出"，一次操作完成归类。
5. **大图灯箱预览**：空格或双击打开，← → 切换，Esc 关闭；缩略图不清晰时不用进切片软件。
6. **右键上下文菜单**：打开、送切片软件、资源管理器定位、复制路径、重命名、收藏、删除。

### 找得到、理得清
7. **智能视图（自动更新）**：全部 / 收藏 / 未打印 / 未分类 / 未打标签 / 最近 7 天添加 / 最近打开 / 重复文件 / 失效文件。把"筛选"变成一键视图。
8. **一键资源管理器定位 + 复制完整路径**：从模型回到磁盘，是本地工具最常被用到的动作。
9. **缩略图尺寸滑块 + 网格/列表 + 深浅主题 + 视图密度**，偏好本地持久化。
10. **统计条**：模型总数、占用空间、各打印状态分布、重复/失效数，一眼看全库。
11. **保存的视图**：把当前一组筛选条件存成自定义视图（如"未打印的拓竹件"），下次一键回到它。

### 数据安全与容错
12. **索引备份 / 导出 / 导入 JSON**：数据全在本机，必须能备份和迁移；每次写入前自动轮转备份，损坏时可从备份恢复。
13. **失效文件"重新定位"**：文件被挪走后，按文件名+大小自动在监控目录找候选，或手动指定；备注、标签、状态不丢失。
14. **重复文件并排对比 + 安全处理**：按内容 SHA-1 分组，另给"疑似重复"（归一化名称+近似大小）；只标记，删除需手动且走系统回收站。
15. **目录自动监视**：新增/删除 3mf 时自动增量更新索引（可开关），不用每次手动点扫描。
16. **撤销上一次批量操作**（Undo 栈）：批量改错了能一键回退，比弹确认框更轻。
17. **扫描排除规则与深度限制**：默认跳过 `node_modules`、`AppData`、回收站、应用自身 data 目录等噪声。

### 一点小趣味
18. **"打印轮盘"**：从未打印的模型里随机挑一个，专治收藏了几百个却永远不知道打哪个。极简实现，但很讨喜。
19. **评分（1~5 星）+ 来源链接 / 作者字段**：卡片上直接点星，备注之外多一层轻量归档维度。

> 明确**不做**（避免范围膨胀）：3D 实时预览渲染、STL/OBJ 等其它格式、云同步、账号体系、切片参数编辑、打印任务下发、AI 自动打标。这些要么与"集中管理 3mf"无关，要么会把本地工具变成重型应用。

## 四、风险与对策

| 风险 | 对策 |
|---|---|
| 极简 3mf 无内嵌缩略图 | 多级回退 + 生成式占位图（按文件名哈希取色，显示扩展名与首字母） |
| 大工程解析慢/占内存 | 增量扫描（size+mtime 未变则跳过）、并发限流、XML 只做轻量正则统计、超阈值跳过精细解析 |
| 索引文件损坏 | 原子写（临时文件 + rename）、写入前自动备份、启动时校验并可一键恢复 |
| 误删用户文件 | 默认"仅移出索引"；删除文件走系统回收站 + 二次确认 + 列出完整路径 |
| 切片软件路径含空格/被占用 | `spawn` 参数数组（不开 shell）、路径存在性校验、启动失败给出可操作提示 |
| 同名/移动导致索引错乱 | 以规范化绝对路径为唯一键，提供重新定位，保留全部人工元数据 |
