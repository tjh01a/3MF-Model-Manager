## 1. 目标与非目标

### 1.1 目标

1. **更美观**：统一图标笔触与语义，消除「同形异名 / 缺图标 / 混搭」；收敛 `--t*` 与 `--ease`，让全站反馈节奏一致。
2. **更简洁**：减少重复视觉噪音（多余徽标、过密分割线、hover 时多层同时变色），不改变信息架构与功能入口。
3. **适度动效提升反馈与流畅感**：把「页面/视图切换、状态反馈、加载提示」三类关键时刻补上短促、可预测、可关闭的动效。
4. **不牺牲既有工程质量**：CSP、离线、零打包器、增量渲染、启动动画、reduced-motion、z-index 体系全部保持。

### 1.2 非目标（明确不做）

- 不引入 React/Vue/组件库、不引入打包器、不引入 Tailwind、不引入 CSS 预处理器；
- 不改 CSP、不放开 CDN / 内联脚本 / 远程字体；
- 不升级 Electron（EOL 单独排期）；
- 不改 `data/library.json` 的字段结构、不改用户已存的 `cat.icon` 值；
- 不重做信息架构、不增删功能入口、不改统计条含义；
- 不做营销级「震启动效」：不加列表 stagger 入场、不加循环呼吸动画、不加全屏转场；
- 不引入 Animate.css / Hover.css / GSAP / Lottie / AutoAnimate（理由见调研 §3 §6）。

## 3. 动效使用场景矩阵（核心设计）

统一原则：**只动 `transform` / `opacity`；时长 ≤220ms；一次只表达一件事；所有场景都有 reduced-motion 与 `ui.motionLevel=off` 的短路。**

| 场景 | 现状 | 目标效果 | 实现手段 | 时长 | 降级 / 注意 |
| --- | --- | --- | --- | --- | --- |
| **S1 视图切换**（网格↔列表、全部模型↔智能视图、分类切换） | `applyViewClass()` 只改 className，内容瞬间替换；`renderGrid()` 可能整块 `replaceChildren` | 内容区轻微交叉淡入 + 8px 上移；标题与筛选 chips 保持稳定，不跟着闪 | `withViewTransition()` helper 包住**状态更新与渲染回调**；仅给 `#view-title` / `#content` 的**根**做命名，不给每张卡片命名 | 180–220ms | `startViewTransition` 缺失 → 直接更新；`#content` 快照必须限定高度区域，避免几百张卡片全量截图掉帧；回调内**禁止 IPC / await 磁盘** |
| **S2 详情 / 设置 / 灯箱等浮层开合** | 各浮层已有 `fade-in` / `modal-in`（220ms），但彼此缓动不统一 | 保留现有时间与 z-index，统一缓动与位移方向；Esc 关闭走对称收尾 | 纯 CSS，复用 `--t-slow`；不引入 View Transitions（浮层是 overlay，不是视图切换） | 180–220ms | 必须保持 `docs/09` §11.3 层级表；确认框仍在最上层 |
| **S3 状态反馈**（收藏、打印状态切换、评分、归类成功、批量操作完成） | 收藏仅颜色过渡；状态徽标无反馈；归类有 `dropfx` 飞入 + 计数弹跳 | 成功操作给一次 120–160ms 的轻微 scale/透明度脉冲；失败给一次短促横向抖动（自绘 keyframes） | CSS class + WAAPI `element.animate()`（一次性、可 `cancel()`）；通过事件委托在 `grid.js` / `bulkbar.js` 挂载 | 120–160ms | **不得**触发 `emitRefresh()` 之外的额外查库；脉冲只作用于被操作的那一个节点，不能全卡片重渲染 |
| **S4 加载 / 等待提示** | 已有启动动画（460ms 最小展示 + 12s 兜底）、`spin` / `shimmer`、扫描进度条、设备进度条 | 补三类缺口：①按钮 pending（扫描、转换、批量删除）②首屏数据到达前的卡片骨架 ③IPC 长等待的轻量提示 | CSS `spin` / `shimmer` 复用；按钮加 `aria-busy` + `.is-pending`；骨架用纯 CSS 渐变，**不新增 DOM 节点层级** | 循环动画 1.2–1.4s；提示 ≤1 行 | 绝不与 `#boot-splash`（9999）叠一层全局遮罩；Toast 已有 210 层级，复用而非新建；`prefers-reduced-motion` 下循环动画改为静态色块 |
| **S5 数据变化 / 列表增删** | `renderGrid()` 指纹增量替换，DOM 节点复用；删除后卡片瞬间消失 | 仅对「单条删除 / 单条新增」做 160ms 淡出淡入；批量刷新（换排序、换筛选）**不加动画** | 在 `renderGrid()` 的 `patch` 分支对 `replaceChild` 的新节点加一次性 class；`full` 分支不加 | 160ms | 阈值保护：`diff.length > 12` 直接跳过动画；**不引入 AutoAnimate**（MutationObserver + 整块替换会放大成几百个动画） |
| **S6 手势 / 悬停反馈** | 卡片 hover 有 translateY(-3px)、工具条滑入、色板上移、check/fav/badges 淡出，共 5 层同时变化 | 收敛为「主位移 1 次 + 工具条 1 次」，去掉同帧多余的 opacity 抖动；按钮 `:active` 补 80ms 下压 | CSS 过渡，统一 `--t-fast` | 80–180ms | 列表模式禁用位移（现有规则保留）；hover 不能成为唯一可达路径（键盘 `:focus-visible` 等价） |
| **S7 侧栏折叠 / 窄屏抽屉** | 已有 220ms `grid-template-columns` 过渡与抽屉 `left` 过渡 | 只统一缓动，不改行为；确认 `prefers-reduced-motion` 下仍瞬间完成 | CSS | 220ms | 不新增动画，避免与 `probe-sidebar` 的 `transitionProperty` 断言冲突 |
| **S8 主题切换** | `html[data-theme]` 瞬时换值，各元素自己的 transition 负责过渡 | 给大块表面加 160ms 背景/文字色交叉淡入（不整页闪白） | CSS transition on `background-color/color`（**非** `all`） | 160ms | 不阻塞 `applyTheme()` 的 `#btn-theme` 图标切换；不写设置之外的状态 |

**明确不做的动效**：卡片入场 stagger、滚动视差、页面级左右滑入、图标循环跳动、全屏 loading 遮罩、任何 >300ms 的转场。

## 6. 验收标准（量化）

### 6.1 功能与兼容

| 项 | 标准 |
| --- | --- |
| 图标完整性 | `probe-icons.js`：54 个 `i-*` id 全部存在、`icon()` 生成的每个 `<use>` 都能命中 symbol、无孤立 symbol、无重复路径；设置页「修好」「打开系统默认应用设置」两个按钮图标可见 |

| 动效可关闭 | `ui.motionLevel=off` 时：无 View Transition、无新增 keyframes、`getComputedStyle` 的 `animationName` 为 `none`；`reduced` 档只保留 opacity 淡入 |
| 系统级 reduce-motion | 开启系统「减少动态效果」后，所有新增动效被压制（含 `dropfx.js` 例外也要纳入），`::view-transition-*` 动画显式 `animation:none` |
| 键盘可达 | 所有 hover 才出现的操作都有 `:focus-visible` 等价路径；转场结束后焦点落在合理元素（`updateCallbackDone` 后显式设置） |
| 层级不破 | `probe-interactions.js` 的确认框层级断言仍通过；新增任何浮层必须写进 `docs/09` §11.3 表 |

| 指标 | 现状基线 | 验收上限 |
| --- | --- | --- |
| 全量渲染 `full` | ~68ms（224 张卡） | ≤100ms |
| 增量渲染 `patch` | ~1ms | ≤5ms |
| 轻量刷新 IPC 次数 | 0（`query/stats/smartCounts`） | 必须仍为 0，新增动效**不得**触发查库 |

- 第三方 LICENSE / NOTICE 归档完整，`README.md` 有致谢与版本锁定说明。

## 7. 风险登记与回退方案

| # | 风险 | 触发信号 | 缓解措施 | 回退方案 |
| --- | --- | --- | --- | --- |
| R1 | **View Transitions 快照导致掉帧**（`#content` 几百张卡） | `probe-perf` full >100ms 或肉眼卡顿 | 只给标题/单个命名元素转场；`#content` 用 `view-transition-name: none` 或限制快照区域；回调内不 await | `ui.motionLevel=off` 或删掉 `withViewTransition()` 包装，DOM 更新逻辑完全不变 |
| R2 | **动画与增量渲染打架**（`replaceChild` 销毁节点上的动画） | 收藏/状态切换后卡片闪烁或不重画 | 动画只作用于**未被替换**的容器，或用 `syncSelectionDom()` 之类的 DOM 同步而非重建；新可见字段必须进 `cardSig()` | 关闭 S3/S5；退回纯 CSS 静态反馈 |
| R3 | **缓动统一破坏既有 40+ 条 transition** | `probe-sidebar` 的 `transitionProperty` 断言失败、侧栏手感变差 | 只改 `--ease` 值并 A/B 截图；侧栏 `grid-template-columns` 过渡单独保留 | 保留 `--ease:ease`，仅新增语义别名，不改现有值 |

## 11. 实施结果与计划偏差（2026-11-15）

用户 2026-11-15 全权授权后按默认假设执行。**Q1 被用户覆写为「高雅、克制、不堆砌」**，
Q2 / Q3 / Q5 / Q9 / Q11 / Q12 走调研文档 §7 的默认假设。以下逐条记录与计划的偏差；未列出的部分按计划落地。

a) **系统 reduce 的判定由「压成 `off`」改为「降到 `reduced`」**。计划 §3 / §6.1 写「开启系统减少动态效果后所有新增动效被压制」（`off` 口径）；本机实测该媒体查询命中 `reduce`，若一律压成 `off`，应用内「完整（`full`）」选项等于摆设。实际：`prefersReducedMotion` 命中时 `full → reduced`，`reduced` 保持 `reduced`，**只保留纯 opacity 淡入**，不做位移 / 转场 / 循环动画；**用户显式 `off` 仍一票否决**，任何情况都是 `off`。降级后的实际档位写 `html[data-motion-effective]`，不回写用户存的 `motionLevel`。

b) **S4 按用户「不堆砌」主动缩减**。计划要新建「卡片骨架屏 + 全局遮罩 + 按钮 pending」三类；实际**未新建骨架屏与全局遮罩**，只保留 `[aria-busy="true"].is-pending` 的**按钮级**样式，业务接入点留给后续。理由：不在 `#boot-splash`(9999) / Toast(210) 之上再叠一层，符合「高雅、克制」。

c) **S5 用 WAAPI `element.animate()` 而不是加 class**。计划写「对 `replaceChild` 的新节点加一次性 class」；增量渲染会复用节点，残留类名可能让下次 patch 带着旧动画。实际改为一次性 `element.animate()`（可 `cancel()`），阈值 **`diff.length <= 12`** 才做；批量刷新（换排序 / 换筛选）完全不加动画。

d) **图标实际映射里 `i-dice` 用了 `dices`**（官方包无 `dice` 这个图标名），其余 55 个按计划；`i-close` / `i-x` 按 `tools/icons/map.json` 都映射到官方 `x`，是**两个独立 symbol、路径相同**，不做去重合并。映射表当时共 56 条（后续新增 `i-globe` 后为 57 条）。

e) **两套 sprite 采用「同一组 id 只换 symbol 内容」实现，而不是计划 §7.1 写的「前缀映射」**。理由：静态 46 处 `<use href="#i-*">` 与 `icon()` 生成的 `<use>` 都不用改，也不需要常驻 `MutationObserver`。`applyIconSet()` 只替换每个 `<symbol>` 的路径内容，id 与 `href` 完全不变；`sprite-legacy.html` 是改造前 54 个自绘路径 + 补齐 2 个的全量备份。

f) **`--ease` 保持 `ease` 不动**（R3 保守方案）。计划 §2 L2 / R3 曾评估「统一 `--ease` 为更有质感的缓动」；实际只新增 `--ease-ui` 与 `--dur-*`（浅色块与深色块各一份），既有 **56 条 transition** 一律不受影响，避免 A/B 回归面扩大。

g) **Electron 仍 33.4.11，未升级**。按计划「独立排期，本次不动」，与视觉改造解耦。

h) **Q3「两步走」实际一次完成 56 个替换**（含补齐 `i-wrench` / `i-gear` 两个缺失图标），并保留 `sprite-legacy.html` 的 legacy 全量备份，可一键切回。

## 12. M6 · 交互反馈补强（2026-11-19）

### 12.1 先修「策略错位」：系统偏好不再硬覆盖应用设置

原实现里，只要系统开了「减少动态效果」，应用内选「完整」也会被压成 `reduced`。
用户反馈很直接：*别的软件和游戏都有动效，为什么这个没有。* 这个判断是对的——
系统开关是**建议**，不是强制；把它做成硬覆盖，用户只会觉得「选了完整却没动效」是 bug。

改动：

| 层 | 改动 |
| --- | --- |
| `settings.ui` | 新增 `motionFollowSystem`（默认 `false`） |
| `motion.js` | `effectiveLevel()`：`off` 一票否决 → 只有 `motionFollowSystem && systemReduce` 才降 `reduced` → 否则按 `motionLevel` |
| `base.css` | 全局限动规则从 `@media` 直接压 `*`，改为 `html:not([data-motion-effective="full"]) *` |
| 设置页 | 外观新增「跟随系统『减少动态效果』」开关；说明文案随系统状态变化 |
| `probe-motion` | 增加 `appWins` 断言（系统 reduce + 应用 full → 实际 full） |

**只改 JS 档位不够**：`base.css` 那条 `@media (prefers-reduced-motion) { * { transition-duration:.001ms } }`
是按媒体查询生效的，属性驱动不到位，CSS 过渡仍被压住——本轮实测踩到，已一并修正。

### 12.2 新增的反馈

| # | 位置 | 行为 | 档位 |
| --- | --- | --- | --- |
| 1 | 按钮 / 图标按钮 / 导航 / 菜单项 / chip | 按下 `scale(.97)`，80ms | full |
| 2 | 列表行、设置行、重复项 | 悬停背景/边框 150ms 过渡 | full/reduced |
| 3 | Toast | 退场 `opacity + translateX(10px)`，180ms（之前是硬删） | full |
| 4 | 快开菜单 `.qpop` | 出现时 `pop-in` 120ms | full |
| 5 | 进度条 / 开关 | 曲线统一到 `--ease-ui`（原先 width 用 `ease`，有先快后顿感） | 所有 |
| 6 | 设置页切 tab | 内容 150ms 淡入 + 4px 上移（同面板内切换，不叠加浮层动画） | full |
| 7 | 统计条数字 | 变化时 `stat-bump` 420ms（抬 1px、放大 6%、闪主色） | full |
| 8 | 同 7（reduced） | 只闪主色 520ms，无位移 | reduced |
| 9 | 备注「已保存」 | 淡入 + 上移 2px，1.8s 后淡出（之前是无样式的裸文本） | full |

reduced 档额外放行**非位移**过渡（透明度/颜色/背景/边框/阴影 150ms）；
否则开了系统限动的机器上所有反馈都是瞬间硬切，反而看不清「刚才发生了什么」。

### 12.3 顺手修的「不流畅」

**详情面板局部刷新会跳回顶部。** 点状态、收藏、标签都会整块重绘 `#detail-body`，
`scrollTop` 被清零——用户正在看成本，点一下「已打印」就被弹回缩略图。
现在 `render()` 记住 `lastRenderId`：同模型的局部刷新保留滚动位置（并 clamp），
换模型才回到顶部并给 140ms 淡入。验证：`probe-detail-smooth`（滚到 260px → 点收藏 → 仍是 260px）。

### 12.4 测试基建：capture 通道关闭节流

`--capture` 的窗口常被判为「被遮挡」，Chromium 会把帧与定时器节流（实测 50ms 定时器被拉到 ~1s）。
动效时长还是 0.001ms 时看不出问题；一旦按真实时长跑，所有 CSS 过渡停在第一帧，
`probe-sidebar` 量到折叠后仍是 232px。

修法：`--capture` / `--smoke` 时追加 `disable-background-timer-throttling` /
`disable-renderer-backgrounding` / `disable-backgrounding-occluded-windows` 三个开关，正常启动不受影响。

同时修正两个**过期断言**（与动效无关，是功能演进后没同步）：

- `probe-interactions`：二级菜单已从 2 项变为 4 项（拓竹直开 / 官方 Orca 直开 / U1 转换 / 转换后官方 Orca）。
- `probe-card-price`：不能假设「库里所有卡片都是 ¥??」——用户真的配了耗材、分配过重量后必然有已知价。

### 12.6 M7：分阶段启动动画与等待反馈（用户反馈后补做）

用户反馈「刚进软件非常卡，开头也没动效」。定位到两个问题：

1. `motion.css` 里启动动画的 `@media (prefers-reduced-motion)` 是裸写的，绕过了 `data-motion-effective`，系统开关一开就把启动动画整个掐掉——这正是「没动效」的直接原因。
2. `app:ready` 是一道粗粒度二元闸门，chokidar 建监听、两次全库统计都压在首屏之前，用户只看到无限转圈，不知道在加载什么。

实施：

- 启动 CSS 保留全内联，进度条增加 `.is-determinate` + `--boot-pct`，阶段文字切换带 200ms 淡入。
- `main.js` 发 `boot:stage` 七阶段；`preload.js` 缓存整段历史并补发；`boot.js` 排队（每阶段 ≥200ms，总等待 ≤900ms）后推到 100% 再淡出。
- chokidar 移到 `startBackground()`（首屏后 350ms），首屏复用 bootstrap 数据省两次全库遍历。
- 摄像头 / 检测按钮加 `.is-loading` 旋转圈与中文提示，reduced/off 档停转但文字保留。

验证（本机）：

```bash
node launch.js --capture=out.png --ui-script=tools/probe-boot.js          # 七阶段齐全、最终 paint、中心可点
node launch.js --capture=out.png --ui-script=tools/probe-devices-cam.js   # loading / stale / detectLoading 全 true
```

`probe-boot` 实测阶段 `starting → dirs → store → data → services → ipc → backend`，时长约 1040ms（排队展示所致），遮罩移除后中心元素为 `card-img`，不被挡。
