## 0. 一句话结论

1. **重量能提，但别指望全库**：3MF 的 `Metadata/slice_info.config` 与内嵌 G-code 头部确实带切片重量（实测样本 `0.6圆底拼接测试.3mf`：`weight=90.39g`、`used_m=30.06m`、`filament type=PETG`）。但全库 133 个可读文件中只有 **25 个（≈19%）** 有重量，108 个没有（未切片 / 极简格式 / 模型分件）。所以成本估算必须是「**自动提取 + 手动填写 + 按体积估算**」三轨并存，不能只靠自动。
2. **耗材库做成独立板块**：和模型库、设备页平级，标题栏一个入口；卡片网格 + 右侧详情栏，视觉直接复用模型库的卡片 / 侧栏样式。数据独立存 `data/filaments.json`（不走 settings，避免和偏好备份混在一起）。
3. **回执落在「已完成打印」智能视图**：这个视图现在是空的（`printed` 状态库里常为 0），正好改成「打印回执列表」——每次完成/失败自动生成一条，含模型、机器、重量、耗材、成本、时间。
4. **价格口径**：统一用「元 / kg」，每克价 = 元每kg ÷ 1000；成本 = Σ(各耗材用量g × 该耗材每克价)。未分配耗材的模型按库里默认耗材单价估算，并明确标注"估算"。

## 1. 调研事实（本机实测）

### 1.1 3MF 里的重量数据：存在，但覆盖率低且格式分三派

实测命令（可复现）：解压 3MF → 读 `Metadata/slice_info.config` + 任意 `Metadata/*.gcode` 头部。

| 来源 | 字段形态 | 实测样例 | 覆盖 |
|---|---|---|---|
| 拓竹 `slice_info.config` 的 plate 段 | `<metadata key="weight" value="90.39"/>` + `<filament id="1" type="PETG" used_g="90.39" used_m="30.06" color="#FFFFFF"/>`（多色时多个 `<filament>`） | `0.6圆底拼接测试.3mf`、`PAINTED_Venom.3mf`（3 色，`used_g=280.15/171.05/49.63`） | 25 个文件有 `weight`；其中 16 个还有逐耗材 `filament` 行（共 47 行） |
| 内嵌 G-code 头部注释 | `; total filament volume [cm^3] : 72.31`、`; total filament weight [g] : 90.39`、`; filament_density: 1.25` | 同上 16 个文件 | 与 slice_info 同时出现，做校验用 |
| 无切片数据 | `slice_info.config` 只有 `<header>`；或 G-code 头没有重量行 | 108 个文件 | **占多数**，必须支持手填 |

**坑点**：`111.gcode.3mf` 的 G-code 头出现 `volume=9297.94 cm³` 但 `weight=11.62g` 的自相矛盾数据（异常文件）。所以提取时要做合理性校验：`0 < weight < 5000g` 才采信，明显矛盾时忽略并让用户填。

**多色分摊**：`filament` 行的 `used_g` 之和 ≈ 总 `weight`，可按此把总成本拆到各耗材。若只有总重没有逐耗材行，就按 `meta.filamentColors` 的槽位数均分（明确标注"均分估算"）。

### 1.2 用户库实际用到的耗材类型

`data/library.json` 统计：`PLA ×207`、`PETG ×100`、`TPU ×3`，共 74 种颜色。→ 预设名字库以 PLA / PETG 为主，TPU/ABS/PC 等按大厂目录补齐即可。

### 1.3 大厂耗材名字库（联网 + 本机预设双向确认）

- **联网**：拓竹官方耗材指南（`bambulab.com/zh/filament/guide`）列出 41 个系列：PLA Basic / Matte / Pure / Translucent / Tough+ / Silk / Silk+ / Wood / Glow / Metal / Sparkle / Marble / Galaxy / CF / Aero / Lite、PETG Basic / HF / Translucent / CF、ABS / ASA / ABS-GF / ASA Aero / ASA-CF、TPU for AMS / 95A HF / 90A / 85A、PC / PC FR、PA6-CF/GF、PAHT-CF、PPA-CF、PET-CF、PPS-CF、Support 系列、PVA。eSUN 官网列出 PLA-Basic / PLA+ / PLA-HF / PLA-Matte / PETG+ / PETG-Matte / ABS+ / PEBA 等。
- **本机预设**（比网页更全，且是用户机器上真实存在的）：拓竹配置文件 2249 个唯一预设名、快造 Orca 3210 个；去掉 `@BBL xxx` / `@base` / `0.4 nozzle` 后缀后得到 838 个干净系列名（Bambu PLA Basic、Bambu PETG HF、eSUN PLA+、Anycubic PLA Matte、Polymaker …）。
- **落地取舍**：**不把 838 个全塞进下拉**（会卡、会淹没有用项）。取「拓竹官方 41 + eSUN 常见 8 + 本机出现频率最高的一批 ≈60~80 个」做成静态预设表 `FILAMENT_PRESETS`（名字 + 默认类型 + 默认颜色 + 建议单价可空），按品牌分组；用户仍可完全自定义。类型下拉固定为 `PLA / PETG / ABS / ASA / TPU / PC / PA / PVA / 支撑 / 其他`。

## 2. 数据模型设计

### 2.1 耗材 `data/filaments.json`（新文件）

```js
{
  schemaVersion: 1,
  updatedAt: <ts>,
  items: {
    [id]: {
      id,                       // 'fil-' + 时间 + 随机
      name,                     // 'Bambu PLA Basic' 或用户自定义
      brand,                    // 'Bambu' | 'eSUN' | '自定义' …
      type,                     // 'PLA' | 'PETG' | 'ABS' | 'ASA' | 'TPU' | 'PC' | 'PA' | 'PVA' | '支撑' | '其他'
      color,                    // '#RRGGBB'（校验后写入，渲染层再校验一次）
      pricePerKg,               // 元/kg，>=0；0 表示未知
      image,                    // 'a1b2…png'（内容哈希文件名）或 null
      note,                     // 备注（可选）
      isPreset,                 // 是否由预设一键创建
      createdAt, updatedAt,
    }
  }
}
```

- 图片：`data/filament-img/<sha1(内容).slice(0,24)>.png`，`shelf://filaments/<file>` 引用；**换图必须换哈希文件名**（immutable 缓存陷阱，见 `docs/09` 陷阱 17）。
- 不删正在被模型/回执引用的耗材：删除时检查 `filamentLinks` 与 receipts，被引用则提示"已有 N 个模型使用，删除后这些模型会变成未分配"（不阻止，但确认）。

### 2.2 模型扩展字段（写进 `library.json` 的记录）

```js
{
  // 新增（自动/手填成本相关）
  weightG,          // number|null —— 从 3MF 提取的总重量，或用户手填
  weightSource,     // 'slice_info' | 'gcode' | 'manual' | 'volume-estimate' | null
  filamentUsages,   // [{ type, color, usedG, slot }] —— 从 slice_info 的 <filament> 行提取；只做展示
  filamentLinks,    // [{ filamentId, weightG }] —— 用户分配的耗材与各自用量；成本计算以此为准
  costNote,         // 备注（如"按均分估算"）
}
```

- `filamentLinks` 加入 `UPDATABLE_FIELDS` 白名单，才能通过 `api.update()` 写入。
- 未分配时：若库里有耗材，按 `meta.filamentColors` 的第 1 个颜色匹配最接近的耗材做"建议价"，但**不自动写库**，只在详情里显示"预计 ¥X（未分配耗材，按默认价估算）"。
- 成本函数（纯函数，放 `src/core/cost.js`，便于单测）：
  ```
  costOf(rec, filaments) -> { total, parts:[{name, grams, pricePerG, cost}], source, complete:boolean }
  ```
  `complete=false` 表示有耗材未分配或价格为 0，UI 上标注"估算"。

### 2.3 打印回执 `data/receipts.json`（新文件）

```js
{
  schemaVersion: 1, updatedAt,
  items: [{
    id, modelId|null,           // 按 jobName 匹配 fileName 得到；匹配不到为 null
    jobName, printerId, printerName,
    result: 'finished' | 'failed',
    startedAt, endedAt,
    durationMin,
    weightG,                    // 优先取模型 weightG，否则从 session 估算
    cost,                       // 生成时的成本快照（耗材以后涨价不改历史回执）
    filamentNames: [],          // 快照
    note,
  }]
}
```

- 最多保留 200 条（超出丢最旧），文件不会无限长大。
- 生成时机：`monitor.js` 的 `finished` / `error` 通知分支 → `services` 落一条；**无模型匹配也落**（jobName 就是名字），在回执列表里显示"未关联模型"。
- **自动回写状态（用户 2026-11-16 确认）**：`finished` 且按 `jobName` 匹配到模型（`fileName` 去扩展名 / 去 `_U1_哈希` 后缀的规范化比对）时，调 `library.setPrintStatus([id], 'printed')` —— 该方法本身幂等，只在状态真正变化时 `printCount++` 并写 `lastPrintedAt`。失败不回写。`error` 只落回执不改状态。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 3MF 重量覆盖率只有 19% | 三轨并存：自动提取 / 手填 / 按包围盒体积×密度估算；所有估算都标注来源，不伪装成精确值 |
| 异常 3MF 的重量数字自相矛盾 | 合理性校验 `0 < w < 5000`，矛盾时忽略并让用户填 |
| 换耗材图片但文件名不变 → 浏览器缓存旧图 | 图片按内容哈希命名，`shelf://filaments/` 同样 immutable；换图即换文件名 |
| 删耗材后模型成本变"未分配" | 删除前显示引用数并二次确认；历史回执存耗材名快照，不受影响 |
| 自动回写 `printStatus` 覆盖用户手动状态 | 用户已确认要自动改：只在 `finished` 且文件名**精确匹配**时回写；模糊匹配不写，宁可漏不可错。`setPrintStatus` 幂等，不会重复计数 |
