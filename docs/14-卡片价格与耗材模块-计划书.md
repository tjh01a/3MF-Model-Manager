## 0. 用户原话与本项目约定

用户原话（三条，含四张截图）：

1. 「模型的价格写到缩略图红框里，例如 ¥20。如果没有价格计算不出重量则 ¥??。」
2. 「耗材与成本上移到〔详情上半部红框〕。」
3. 「这里增加我们的耗材库模块，所有与耗材有关的，以及我们之前做的耗材相关项目放在耗材库模块里面。」

用户补充（重要）：

> 「红框只是大致位置，具体放哪里你要考虑 UI 的一致性美观性。」

**这条补充改变了执行方式**：四个红框只是「意图指针」，不是像素级落位指令。最终位置必须从现有 UI 的设计语言出发决定，并在计划书里写清「为什么放这里」，让用户可执行前审核。

## 1. 需求理解（逐条）

### 1.1 需求 1 —— 卡片上显示模型价格

**用户意图**：在模型库卡片（缩略图卡片）上看一眼就知道这个模型大概多少钱，不用点进详情。有价格就显示具体金额（示例 ¥20），算不出来就显示占位符 `¥??`。

**截图 1 红框实况**（已放大核对）：
- 红框位于**卡片信息区第二行**（`7.2 MB · 1 个对象 · 1 小时前` 那一行）的**右端**，与第一行标题、第三行"分类 chip + 星级"上下相邻。
- 卡片信息区当前结构（`grid.js:cardHtml`）：
  ```
  .card-info
    ├─ .card-title    标题
    ├─ .card-meta     大小 · 对象数 · 相对时间
    └─ .card-sub      chip（备件维修）  +  .card-stars（★★★☆☆，margin-left:auto 靠右）
  ```
- 红框正好在 `.card-meta` 行右侧的空白，不与 chip / 星级重叠。

**落位决策（UI 一致性）**：

> **把价格做成 `.card-price` 徽标，放在 `.card-meta` 行（大小·对象数·时间那一行）的右端、`margin-left:auto` 靠右**——这正是红框画的精确位置。

理由（执行前放大截图复核后修正：初稿误判为 chip/星级行，实际红框在 meta 行）：
1. `.card-info` 现有三行是全局统一契约（`index.html` DOM CONTRACT + `components.css:729-739`），加第四行会改变所有 153 张卡片的高度和视觉节奏。
2. 第三行 `.card-sub` 已有分类 chip + 5 颗星，在最小 140px 卡片上几乎占满；价格再塞进去会被 `overflow:hidden` 裁掉。而第二行 `.card-meta` 的文字通常只占六成宽，右端有天然留白——红框也正画在这里。
3. 价格与"大小 / 对象数 / 时间"同属模型的**客观度量信息**，放一行在信息架构上比放到"分类 / 评分"行更同质。
4. 徽标字号 11px、整数金额不带小数，复用 `--accent` / `--text-mute` 变量，浅深主题自动跟随，不引入新配色。
5. 列表模式 `.card-meta` 是固定 130px：改成 flex 后让文字 `min-width:0 + ellipsis` 先收缩，价格 `flex:0 0 auto` 始终可见。

**价格口径**（与用户示例一致）：
- 能算出成本（`cost.total > 0` 且 `complete`）→ 显示 `¥20.00` 风格的两位小数金额；整数金额如 ¥20 显示为 `¥20`，避免 `¥20.00` 在 140px 窄卡片上太宽。
- 算不出（无重量 / 无耗材单价 / 未分配耗材）→ 显示 `¥??`，`title` 提示"未取到重量或未分配耗材，点进详情可估算"。
- **不需要新增 IPC**：卡片渲染时同步拿不到成本（成本是异步 IPC）。方案见 §2.1。

**现状数据**（实测本机 `data/library.json`）：153 个模型，仅 1 个有 `meta.weightG`，0 个有 `filamentLinks`，0 个有 `filamentUsages`，耗材库 0 条。因此**绝大多数卡片会显示 `¥??`**——这与用户"算不出就 ¥??"的预期一致，属于数据未完善，不是 bug。计划里要把这一点写清楚，避免用户误以为功能没生效。

### 1.2 需求 2 —— 详情面板「耗材与成本」上移

**用户意图**：把当前埋在详情最底部的"耗材与成本"区块，移到详情上半部，让它和其他概览信息一起出现在首屏，不用滚到底。

**截图 2 / 3 实况**（已放大核对）：
- 截图 2（红框=要移动的对象）：详情当前顺序为
  ```
  大图+按钮 → 标题+状态 → 分类/标签 → 评分/收藏 → 4 个统计块（打印次数/最近打印/最近打开/打开次数）
  → 备注 → 来源/作者 → 文件信息 → 3MF 内信息 → 【耗材与成本 ¥0.00 估算…】 → 重复模型
  ```
- 截图 3（红框=目标大致区域）：红框在**4 个统计块的右侧空白**，紧邻评分/收藏行下方，在"备注"之上。也就是说用户希望成本信息出现在**统计块这一带**。

**落位决策（UI 一致性）**：

> **把 `#detail-cost` 从详情底部整体移到"统计块"之后、"备注"之前，作为详情中部第一个强调区块**。不插进统计块内部（统计块是 4 个等宽 `.stat` 卡片，内部是 `flex` 等分布局，塞进一个结构化成本区会破坏它们的对称）。

理由：
1. 统计块之后、备注之前是详情的"概览信息带"——用户打开详情第一屏就能看到，符合"上移"意图。
2. 保持 `detail-section` 的统一分隔线（`.detail-body .detail-section` 上边框），整体感与"文件信息/3MF 内信息"一致，只是位置提前。
3. 成本区本身有金额大字 + 来源标签 + 分配按钮，是结构化内容；插进 `.stat-row` 会让 4 个统计块变 5 个不等宽项，视觉失衡。
4. 移动的是**整个 `#detail-cost` 区块**（含 `fillCost()` 异步填充、分配耗材/填重量按钮），不拆散、不重写逻辑，只改 `render()` 里 `parts.push()` 的顺序——改动面最小、回归风险最低。

**保留细节**：
- 异步填充 `fillCost(m)` 里的 `currentId !== m.id` 防串仍有效（区块只是换了 DOM 位置，id 不变）。
- 事件委托绑在 `#detail-body` 上，`data-act="cost-assign"` / `cost-weight` 照常工作，无需改 `dispatch()`。
- 三个视图（详情、回执、耗材库）都由 `#detail-cost` 单一来源驱动，避免重复渲染。

### 1.3 需求 3 —— 侧栏「耗材库」模块，收纳所有耗材相关功能

**用户意图**：侧栏新增一个模块分组，把所有与耗材/成本相关的功能入口集中到那里，形成一个功能完整的"耗材库模块"。

**截图 4 实况**（已放大核对）：
- 红框位于侧栏**「分类」区的"新建分类"行下方**与**「标签」区（当前"暂无标签"）**之间——也就是用户希望在这两个区附近新增一个导航分组。
- 侧栏当前分组顺序（`sidebar.js:GROUPS` + `index.html`）：
  ```
  模型库（全部模型/收藏/最近打开）→ 智能视图（已完成打印）→ 质量检查（重复文件/失效文件）
  → 分类 → 标签 → 我的视图
  ```

**落位决策（UI 一致性）**：

> **新增侧栏分组「耗材与成本」，位置放在「质量检查」之后、「分类」之前**，而不是红框画的"分类与标签之间"。

理由：
1. 侧栏已形成清晰的两段式结构：`模型库 / 智能视图 / 质量检查` 是**系统级导航**（点击切换主内容区），`分类 / 标签 / 我的视图` 是**用户组织维度**（管理模型的归类）。耗材库是"系统级功能模块"，与前者同类，放前面符合信息架构。
2. 如果插在"分类"与"标签"之间，会打断"分类—标签—视图"这组连续的组织维度，破坏用户已有的肌肉记忆和视觉分组。
3. 用户明确说红框只是大致位置，这条补充正是授权我们从一致性出发微调。放在质量检查之后，仍然是"侧栏中下部、分类之前"，与红框意图（在侧栏加一个导航分组）完全吻合。

**「耗材库模块」包含什么**（用户："所有与耗材有关的，以及我们之前做的耗材相关项目"）：

> 模块 = 一个侧栏分组标题 + 若干导航项。分组内**入口指向现有功能**，不重复造轮子：

| 导航项 | 点击行为 | 现有实现 | 说明 |
|---|---|---|---|
| **耗材库** | 打开耗材库浮层 | `views/filaments.js` 的 `openFilaments()` | 就是标题栏 `#btn-filaments` 打开的那个浮层，这里给侧栏一个并列入口 |
| **打印回执 / 成本账本** | 切到 `smart='printed'` 内容区 | `views/receipts.js` + `app.js` 的 `mode==='receipts'` | 就是现在「智能视图 → 已完成打印」指向的回执视图 |

**关于「已完成打印」是否移动**：
- 现状：`SMART_VIEWS` 里 `printed` 归在 `smart` 组，点击后主内容区显示的是**打印回执**（不是普通模型网格）——它本质是"耗材成本账本"的一部分，放在"智能视图"里本来就有点名不副实。
- 决策：**把 `printed` 从 `smart` 组移入新的 `cost` 组**，标签改为「打印回执 · 成本账本」。这样"所有耗材相关项目"真正聚到一处；「智能视图」组随之只剩空组 → 一并移除该组标题（否则留一个空分组很难看）。
- 兼容性：`state.query.smart === 'printed'` 的语义、`app.js` 的 `mode==='receipts'` 路由、`tools/probe-receipts.js` 都不变，只是侧栏按钮换了个分组和标签。单测/探针若按 `data-smart="printed"` 定位，依然命中。

**分组视觉**：复用现有 `.nav-sub` / `.nav-sub-label` / `.nav-item` 样式（`sidebar.js:renderLibrary` 已按 `GROUPS` 循环渲染），只是新增一个 `group:'cost'`，无需新 CSS。图标沿用 `i-box`（耗材）与 `i-check`（回执），与现有图标集一致。

## 2. 技术方案

### 2.1 卡片价格的数据来源（关键：避免 153 次 IPC）

卡片是**同步渲染**的（`grid.js:cardHtml` 拼字符串），而成本 `api.modelCost(id)` 是**异步 IPC**。逐卡调用会在 153 张卡上发 153 次 IPC，瞬间拖垮首屏。

**方案**：新增一个**批量成本接口** `modelsCosts()`，一次 IPC 拿到全部 {id → cost} 映射，渲染层缓存到 `state.costs`，卡片同步读缓存。

| 层 | 改动 |
|---|---|
| `src/core/cost.js` | 无改动，`costOf()` 已是纯函数 |
| `electron/services.js` | 新增 `modelsCosts()`：遍历 `library.list()`，对每个模型调 `costOf(rec, filaments.list())`，返回 `{ [id]: { total, complete, weightG } }` |
| `electron/ipc/index.js` | handlers 新增 `modelsCosts: () => services.modelsCosts()` |
| `electron/preload.js` | METHODS 新增 `'modelsCosts'` |
| `src/renderer/js/api.js` | METHODS 新增 `'modelsCosts'` |
| `src/renderer/js/state.js` | 新增 `costs: {}` 字段 |
| `src/renderer/js/app.js` | `bootstrap()` 后与 `doRefresh()` 里并行拉一次 `api.modelsCosts()`，写入 `state.costs`；`filaments:changed` / `receipts:changed` 时刷新成本缓存并重渲染网格 |

**缓存刷新时机**（保证改价后卡片价格跟着变）：
- 首次 `bootstrap()` 完成拉一次。
- `emitRefresh()` 触发的重刷新里，带上成本刷新（与 `query/stats` 并行）。
- 监听 `filaments:changed` 与 `receipts:changed` 窗口事件 → 重拉成本 + `renderGrid()`。

**卡片指纹**（`grid.js:cardSig`，已明确写在 `index.html` DOM CONTRACT 里"新增可见字段必须进指纹"）：
- 加入 `costTxt = state.costs[m.id] ? ... : '??'`，保证耗材改价 / 分配耗材后卡片会重画。

**成本来源不落库**：卡片价格是派生值，只存在内存 `state.costs`，不写 `library.json`，不需要备份（延续 docs/13 的"耗材数据独立"决策）。

### 2.2 详情成本上移

仅改 `detail.js:render()` 里 `parts.push()` 的顺序：把 `#detail-cost` 的 push 从"3MF 内信息之后"移到"统计块 detail-section 之后、备注 detail-section 之前"。**零逻辑改动**。

### 2.3 侧栏模块

仅改 `sidebar.js`：
1. `SMART_VIEWS` 里 `printed` 的 `group` 从 `'smart'` 改为 `'cost'`，`label` 改为 `'打印回执 · 成本账本'`。
2. 新增一条 `{ key:'filaments', label:'耗材库', icon:'i-box', group:'cost', action:'open-filaments' }`（非 smart 项，用 `data-act` 触发）。
3. `GROUPS` 在 `quality` 后插入 `{ key:'cost', label:'耗材与成本' }`；移除只剩空项的 `smart` 组。
4. `renderLibrary()` 对 `v.action === 'open-filaments'` 渲染 `data-act="open-filaments"` 的按钮，`onClick()` 里调用 `openFilaments()`（从 `views/filaments.js` import）。
5. `index.html` DOM CONTRACT 注释同步更新分组说明。

> 注意：`window` 事件 `shelf:refresh` 与 `state.query.smart` 语义不变，`probe-sidebar.js` 的 `EXPECTED_SMART` 数组需要同步（它断言侧栏智能视图项）。

## 4. 风险与对策

| 风险 | 对策 |
|---|---|
| 153 张卡片逐条 IPC 卡死 | 批量 `modelsCosts()` 一次拿全，内存缓存，卡片同步读 |
| 耗材改价后卡片价格不更新 | `filaments:changed` / `receipts:changed` 事件触发重拉 + 进指纹重画 |
| 绝大多数模型显示 `¥??` 被误认为 bug | 计划书/README/交付说明写清"当前数据未填重量和单价"，并提供详情里"填重量/分配耗材"的引导 title |
| 卡片最小宽度 140px 放不下金额 | 价格徽标用 `font-size:10px`、整数不带小数、超窄时 `flex-shrink` 让星级先缩；列表模式 `.card-sub` 172px 同样容得下 |
| "已完成打印"迁移后用户找不到 | 新分组标签明确写「打印回执 · 成本账本」，并在 README 说明；`data-smart="printed"` 不变，探针/快捷键兼容 |
| 智能视图组被移除后 GROUPS 循环空指针 | `renderLibrary()` 按组过滤 `SMART_VIEWS`，空组不渲染；移除组前确认无遗留项 |
| 探针写入真实 data | 探针用测试数据，跑完清理，参考上一轮 `final cleanup` 流程 |

## 6. 明确不做

- 不新增自动"猜价格"逻辑（不按体积默认估算塞给卡片）—— 算不出就如实 `¥??`，尊重数据现状。
- 不在卡片上显示成本明细（克数、耗材名）—— 卡片只放一个总金额，明细留给详情。
- 不改 `state.query.smart === 'printed'` 的语义与回执视图逻辑。
- 不改价格口径（元/kg ÷ 1000 × 克），延续 docs/13。
- 不把派生成本写入 `library.json`，不做备份（延续 docs/13）。
