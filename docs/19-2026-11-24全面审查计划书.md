# 2026/11/24 全面审查计划书

## 0. 目标与原则

本次审查从零开始，对 PrintShelf / 3MF 模型管理器当前工作区做一次**从代码到功能、从自动化到打包、从数据到交互**的全面审查，并在发现问题时由审查方自行完成复现、定位、修复、补测和回归，不停留在建议层面。

执行原则：

1. **证据优先**：问题必须有文件、行号、可复现路径或测试输出；不凭感觉下结论。
2. **数据安全优先**：任何可能丢失模型索引、设置、回执、预设、源文件的路径按 P0 处理。
3. **用户可感知优先**：按钮无反应、错误提示缺失、交互不一致、数据展示错误按 P1 处理。
4. **先隔离再验证**：破坏性测试只在临时数据目录或临时样本上跑；不污染用户真实 `data/`。
5. **修复必须闭环**：每个修复都要有对应测试或 UI 探针；纯代码优化也要能被回归验证。
6. **不扩大发布范围**：本次审查默认不推送 GitHub、不发 Release、不升级版本号；除非用户另行明确要求。

### 2.2 重点回归路径

## 3. 自动化测试策略

### 3.1 测试分层

| 层级 | 工具 | 目的 |
| --- | --- | --- |
| 语法/契约哨兵 | `tools/syntax-check.js`、`tools/check-ipc-contract.js` | 防止改完主进程起不来；防止 IPC 三方白名单漂移 |
| 纯 Node 单元测试 | `tests/run-tests.js` 等 | core 层逻辑、解析、数据、成本、回执、分类、来源、权重 |
| 端到端冒烟 | `tests/e2e-smoke.js` | 临时数据目录内跑完整扫描/查询/分类/备份/导出链路 |

| 构建验证 | `tools/build-all.js --force` 或分步构建 | 确认打包脚本、资源、产物文件完整 |

### 3.2 数据隔离

- 所有破坏性测试必须使用 `PRINTSHELF_DATA_DIR` 指向临时目录。
- UI 探针原则上只读或只操作 DOM；确需注入假数据时，只注入 renderer 内存，不调用写接口。
- 探针统一监听 `.toast-error`，验收要求 `toastErrors: []`。
- 每次全量测试后核对真实 `data/u1-cache/`、真实库记录数、关键文件 mtime 未被测试改写。

### 3.3 覆盖目标

- **代码覆盖**：所有 core 模块至少被静态审读；高风险模块（store/scanner/library/printers/receipts/cost/devices）必须深读并验证关键分支。
- **功能覆盖**：第 2.1 节 13 类功能逐项给出结论：通过 / 已修复后通过 / 遗留风险。
- **交互覆盖**：主界面、回执、设备、耗材、详情、设置、分类提醒、来源按钮、窄屏/深色至少各有一条走查证据。
- **契约覆盖**：preload、api、IPC handler 三方方法一致；事件白名单与转发一致；DOM 类名与 CSS 一致。
- **测试覆盖**：`npm run selftest` 全绿；新增修复必须对应新增断言或探针。

## 4. 风险优先级

| 等级 | 定义 | 示例 | 处理要求 |
| --- | --- | --- | --- |
| P0 | 数据丢失、隐私泄露、主进程崩溃、源文件被破坏 | 空库重置、误删模型、越界写文件、测试污染真实数据 | 立即修复；修复前禁止发布；必须补回归测试 |
| P1 | 核心功能不可用或用户可明显感知错误 | 按钮无反应、弹窗不出现、价格错误、回执删错对象、设备无法移除 | 本轮修复；补 UI 探针或单测 |
| P2 | 健壮性/一致性问题，特定条件下触发 | 连接失败文案不清、缓存过期判断不准、状态不同步、边界值异常 | 本轮评估，能安全修复就修复；否则记录遗留风险 |
| P3 | 体验、文案、可维护性、低概率边界 | 文案歧义、按钮拥挤、重复代码、日志冗余 | 低风险项直接修；其余列入后续建议 |

## 5. 执行流程

1. **准备**：记录当前 Git 状态、文件清单、测试基线；写本计划书。
2. **并行审查**：按 core、electron/IPC、renderer UI、测试/构建/文档四路并行深读；主代理复核每条发现。
3. **基线测试**：跑语法哨兵、全量 selftest、IPC 契约、关键 UI 探针，记录原始结果。
4. **复现**：对每个问题用最小脚本、单测或 UI 探针复现；无法复现的降级为观察项，不直接改代码。
5. **修复**：按 P0 → P1 → P2 → P3 顺序修复；每次只改一个逻辑单元，避免混杂。
6. **补测**：新增/调整测试，确保修复前有失败证据、修复后有通过证据。
7. **全量回归**：再次跑语法、契约、selftest、相关探针、构建验证。
8. **报告**：输出正式报告，列明执行过程、审查结果、测试覆盖与结果、已修复 bug、优化项、遗留风险、后续建议。

## 8. 并行分工约定

- **core-reviewer**：深读 `src/core/**`，重点查数据一致性、路径安全、解析边界、成本/回执、设备网络。

子代理只允许返回证据和结论；是否修改代码由主代理统一决策，避免并发写冲突。
