# 3MF模型管理器 打包说明（项目目录仍叫 PrintShelf）

面向「把 3MF模型管理器 发给不懂技术的朋友」这条链路。全程只用 Node 脚本 + 复制 Electron 运行时，
**不需要** electron-builder / electron-packager / NSIS / Inno Setup，也不需要联网。

产物命名取自 `package.json`：`productName`（当前 `3MF模型管理器`）+ `version`（当前 `1.1.0`）。
版本号变化后，下列文件名中的 `1.1.0` 会跟着变。1.0.x 时期的英文命名产物（`3MF-Model-Manager-*`）是历史遗留，不是当前脚本的输出。

## 一、打包前的前置条件

1. 机器上已经 `npm install` 过，存在：
   - `node_modules/electron/dist/electron.exe`（当前实测 Electron 33.4.11；`package.json` 声明 `^33.2.0`）
   - `node_modules/adm-zip`、`node_modules/chokidar` 及其传递依赖
2. Node.js 20 以上（本项目实测 Node 22）。
3. 打包过程只读源码，**不会改动** `electron/`、`src/`、`package.json`，也不会碰 `data/`。

## 二、怎么打包

在项目根目录执行一条命令：

```bash
node tools/build-all.js
```

想连已有 zip 一起覆盖重建：

```bash
node tools/build-all.js --force
```

也可以分步执行：

```bash
node tools/build-portable.js   # 只出绿色版目录
node tools/build-zip.js        # 只压 zip（已存在则跳过，--force 覆盖）
node tools/build-setup.js      # 只出安装版 exe（需要先跑过 build-portable.js）
```

## 四、怎么给朋友用

1. 把 `dist/3MF模型管理器-1.1.0-portable.zip` 发过去（微信/网盘都行）；想要向导式安装就发 `dist/3MF模型管理器-1.1.0-setup.exe`。
2. 让对方解压到**一个固定的文件夹**（不要直接在压缩包里双击运行）。
3. 双击 `3MF模型管理器.exe` 即可。第一次启动 Windows 可能弹 SmartScreen，
   点「更多信息」→「仍要运行」。
4. 想要桌面图标：双击 `一键安装.bat`，安装到
   `%LOCALAPPDATA%\Programs\3MF模型管理器`，自动建桌面 + 开始菜单快捷方式并启动一次。
5. 用户数据默认在程序目录下的 `data/`；如果安装目录不可写（例如装进 `Program Files`），
   程序会自动回退到系统用户数据目录下的 `data/`（Electron `userData/data`）。
   也可以用环境变量 `PRINTSHELF_DATA_DIR` 显式指定。卸载时保留，复制该目录即可迁移/备份。

## 五、已知限制

- **没有代码签名**：首次运行会触发 Windows SmartScreen 提示，属正常现象，不是病毒。
- **未做 asar 打包**：应用代码以散文件放在 `resources/app/`，启动稍慢一点，
  但排查问题方便（改完文件不用重新打包就能验证）。
- **数据默认跟程序目录绑定**：绿色版默认数据目录是 exe 同级的 `data/`；
  用户如果把 exe 单独剪切到别处，会看到一份空库。安装版不可写时回退到 `userData/data`。
- **只出 Windows x64**：脚本里写死 `win-x64`，没有做 arm64 / macOS / Linux 分支。
- **依赖必须装好**：脚本不联网，缺 `node_modules/electron` 或运行期依赖会直接报错退出。
- **不支持自动更新**：升级方式是把新版本解压到新文件夹，再把旧 `data/` 复制过去。
- **zip 压缩在内存里完成**：机器内存小于 4GB 时压缩 270MB 的 Electron 会吃紧。

## 六、冒烟自检

打包后可以直接对 exe 跑无头自检（不会碰用户的真实模型库，smoke 自带隔离数据目录）：

```bash
"dist/3MF模型管理器-1.1.0-win-x64/3MF模型管理器.exe" --smoke --smoke-allow-empty
```

有样本目录时可以指定扫描根，验证真实的扫描 + 缩略图链路：

```bash
"dist/3MF模型管理器-1.1.0-win-x64/3MF模型管理器.exe" --smoke --smoke-seed=<样本目录>
```

当前 `electron/main.js` 已按 `process.defaultApp` 区分开发/打包参数起点，并支持
`--smoke-seed=<dir>` / `--smoke-allow-empty`，上面两条命令在打包版里可用。
实测输出形如 `"ok": true`、`ipcHandlers: N`、`thumbs.count: M`。
其中 `ipcHandlers` 的数值是**历史基线（旧记录为 124），以当前 `npm run selftest` / smoke 实际输出为准**。

## 七、历史问题（已修，保留记录）

1. **命令行参数被吃掉一个（已修）**
   早期 `electron/main.js` 用 `process.argv.slice(2)` 取参数，打包版第一个参数会被吞掉。
   现在改为 `process.argv.slice(process.defaultApp ? 2 : 1)`，2026-11-19 修复。
2. **smoke 的扫描种子路径是开发目录假设（已修）**
   早期 `runSmoke()` 固定用工作区上一级作种子，打包后指向 `<程序目录>/resources/` 而没有 `.3mf`。
   现在打包版改读 `--smoke-seed=<目录>`；不给种子时配合 `--smoke-allow-empty` 判定。
