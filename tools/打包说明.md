# PrintShelf 打包说明

面向「把 PrintShelf 发给不懂技术的朋友」这条链路。全程只用 Node 脚本 + 复制 Electron 运行时，
**不需要** electron-builder / electron-packager / NSIS / Inno Setup，也不需要联网。

## 一、打包前的前置条件

1. 机器上已经 `npm install` 过，存在：
   - `node_modules/electron/dist/electron.exe`（Electron 33.4.11，约 269MB）
   - `node_modules/adm-zip`、`node_modules/chokidar` 及其传递依赖
2. Node.js 20 以上（本项目实测 Node 22）。
3. 打包过程只读源码，**不会改动** `electron/`、`src/`、`package.json`，也不会碰 `data/`。

## 二、怎么打包

在项目根目录执行一条命令：

```bash
node tools/build-all.js
```

想连已有 zip 一起覆盖重建：

```bash
node tools/build-all.js --force
```

也可以分步执行：

```bash
node tools/build-portable.js   # 只出绿色版目录
node tools/build-zip.js        # 只压 zip（已存在则跳过，--force 覆盖）
```

## 三、产物在哪

| 产物 | 路径 | 说明 |

| 绿色版目录 | `dist/PrintShelf-1.0.0-win-x64/` | 解压即用，双击 `PrintShelf.exe` |

## 四、怎么给朋友用

1. 把 `dist/PrintShelf-1.0.0-portable.zip` 发过去（微信/网盘都行）。
2. 让对方解压到**一个固定的文件夹**（不要直接在压缩包里双击运行）。
3. 双击 `PrintShelf.exe` 即可。第一次启动 Windows 可能弹 SmartScreen，
   点「更多信息」→「仍要运行」。
4. 想要桌面图标：双击 `一键安装.bat`，安装到
   `%LOCALAPPDATA%\Programs\PrintShelf`，自动建桌面 + 开始菜单快捷方式并启动一次。
5. 用户数据在程序目录下的 `data/`（安装版在安装目录的 `data/`），
   卸载时保留，直接复制该目录就能迁移/备份。

## 五、已知限制

- **没有代码签名**：首次运行会触发 Windows SmartScreen 提示，属正常现象，不是病毒。
- **未做 asar 打包**：应用代码以散文件放在 `resources/app/`，启动稍慢一点，
  但排查问题方便（改完文件不用重新打包就能验证）。
- **数据跟程序目录绑定**：默认数据目录是 exe 同级的 `data/`，
  用户如果把 exe 单独剪切到别处，会看到一份空库。
- **只出 Windows x64**：脚本里写死 `win-x64`，没有做 arm64 / macOS / Linux 分支。
- **依赖必须装好**：脚本不联网，缺 `node_modules/electron` 或运行期依赖会直接报错退出。
- **不支持自动更新**：升级方式是把新版本解压到新文件夹，再把旧 `data/` 复制过去。
- **zip 压缩在内存里完成**：机器内存小于 4GB 时压缩 270MB 的 Electron 会吃紧。

## 六、冒烟自检

打包后可以直接对 exe 跑无头自检（不会碰用户的真实模型库，smoke 自带隔离数据目录）：

```bash
"dist/PrintShelf-1.0.0-win-x64/PrintShelf.exe" --smoke
```

实测结论（2026-11-19，Electron 33.4.11）：

- **上面这条命令在打包版里不生效**：进程静默退出（exit 0，无输出）。
  原因见下一节，属源码侧的 argv 解析问题，与打包文件无关。
- 打包完整性用下面的方式验证通过：把产物复制一份到临时目录，
  放一个 `.3mf` 到 `<副本>/resources/`（smoke 的扫描种子目录），再执行
  `./PrintShelf.exe --dummy --smoke`，得到 `"ok": true`、
  `ipcHandlers: 124`、`thumbs.count: 1`（缩略图由 vendor/bedready 真实生成）。

## 七、打包版 `--smoke` 的两个已知问题（源码侧，打包脚本未改动源码）

1. **命令行参数被吃掉一个**
   `electron/main.js` 用 `process.argv.slice(2)` 取参数。开发模式下
   `argv = [electron.exe, '.', '--smoke']` 正好；打包模式下 Electron 不会塞 app 路径，
   `argv = [PrintShelf.exe, '--smoke']`，`slice(2)` 得到空数组，
   `--smoke` 被丢掉，程序按正常模式启动。
   建议改成 `process.argv.slice(app.isPackaged ? 1 : 2)`（或用 `process.defaultApp` 判断）。
2. **smoke 的扫描种子路径是开发目录假设**
   `runSmoke()` 里 `const seed = path.resolve(__dirname, '..', '..')`：
   开发时指向项目上一级工作区（真实 3MF 都在那），打包后指向
   `<程序目录>/resources/`，里面没有 `.3mf`，于是
   `added: 0 / total: 0 / thumbs.count: 0`，`ok` 恒为 `false`。
   建议打包模式下换成一个明确的样本目录参数（如 `--smoke-seed=<dir>`）。

所以「对打包产物跑 `--smoke` 拿到 ok:true」在源码修掉这两点之前做不到；
在那之前请用上一节的临时副本方式验证打包完整性。
